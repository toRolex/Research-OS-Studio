# 证明义务清单

从完整证明提取以下六类记录，作为审查报告中的自然 Markdown 表或列表。小证明可合并展示，但六类检查均需覆盖。提取与裁定分开：`claimed discharge` 是作者声称的论证位置，不是“已证”。

## 1. Dependency DAG

节点为 Definitions / Assumptions / Lemmas / Theorems；边表示“使用”。先合并全篇依赖，再查环，包括语义循环：例如 Lemma A 使用某个推论，而该推论又依赖 A。前向引用本身不必错误，但需找到其完整证明且无循环。

## 2. 假设使用表

对每个定理和引理：

- 列出每条声明的假设及作者声称证明该条件的位置。
- 对每个**应用点**逐条核对条件是否真正被满足；定理陈述里有该条件，不代表调用者已证明它。
- 没有论证位置标为“未提供出处”；有位置但论证不足标为“未建立”，不要混同。
- 追踪实际使用的最小假设集合，区分仅写出但未使用、实际使用却未声明的条件。

## 3. Typed Symbol Table

记录每个符号的类型、定义域、维数、性质和参数依赖，例如：

```text
κ : scalar ∈ (0,1), depends on (d, α_t, Σ, μ)
u* : vector ∈ ℝ^d, u* = C^{-1}m
B^even : matrix ∈ ℝ^{(L+1)×(L+1)}, symmetric PSD（待核实性质）
Ψ_v : function ℝ → ℝ, analytic in (ζ,κ)（待核实）, parity determined by v
```

符号换义、类型不一致、维度不匹配、把性质声明当成证明，均进入发现清单。

## 4. Canonical Quantified Statements

为每个定理/引理写明量词、定义域和取极限顺序。此处是审查转述，不修改原命题：

```text
∀K ≥ 3, ∀π ∈ Π_K^{ms,∘} \ E_K, ∃κ_0 > 0, ∀κ ∈ (0, κ_0):
  h_act^{(K,π)} = Θ(κ^{α_K^act})，对 π 的紧子集一致
```

检查 κ₀ 是否依赖 K、π、d；∀/∃ 次序是否等价于原文。无法精确转述时标为 UNCLEAR 并指出需用户澄清处，不替原文挑一个更容易证明的解释。

## 5. Micro-Claim Inventory

每个“显然”“可得”“标准论证”、非平凡不等式、WLOG 和运算交换都成为带编号的义务。使用 sequent 形式：

```text
MC-17
Context: Lemma 3.1; κ < κ_0; Z_κ 的 2m+2 阶矩有界
⊢ Goal: P̂_0 正定
Rule: 连续分布支撑上单项式线性无关
Side-conditions: 原点邻域密度为正
Claimed discharge: §B.2 以 GMM 弱收敛论证
Review: 单独核查弱收敛是否足以推出所需密度条件
```

每项必须有上下文、目标、规则、所有侧条件及作者给出的证明位置；缺一项就保留明确缺口。编号只供人类追踪，不建立统一机器 schema。

## 6. Limit-Order Map

为每个渐近式记录依次趋于什么、固定什么、在哪个集合一致：

```text
h_act = Θ(κ^α)：κ→0；固定 K；对 Π_K 的紧子集内 π 一致
a_act ~ (b/a)n：n→∞；固定 κ,K,π；且 x_K ≪ 1
```

检查交换极限是否获证；所有 O、o、Θ、≲ 的常数是否依赖 d、n、K 等。量级相同不能自动推出等式或零值。

## 合并后的完成检查

每个 theorem/lemma application 和每个非平凡步骤已在表中；跨节符号一致性和全局循环检查已完成；未读依赖、缺失出处及未完成的数学裁定都有明确记录。覆盖不全时只报告局部审查，不宣布全篇通过。
