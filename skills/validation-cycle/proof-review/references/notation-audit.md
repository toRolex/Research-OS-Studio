# 证明符号审计

正确性检查后、返回审查报告前使用。用户问符号、输出以定理为主，或某一步含至少五个非标准符号时，完整核查。reviewer 只在返回的 Markdown 中记录检查与建议，不编辑或保存文件；获授权执行者可按建议改写并保存报告。阈值是表达编辑标准，不是数学定律；确实降低总复杂度的超阈值记号可保留，但须逐项解释。

问题分类以 proof-review 的数学审查规则为准；本目录检查见 [证明审计准则](proof-audit-rubric.md)，记录格式见[审计输出约定](audit-output-contract.md)，本地及回传分支见[提示模板](dispatch-prompts.md)。

## 必需清单

先从定理陈述、算法更新和最终结论确定语义中心：状态变量、策略或分布、算子、目标函数及其依赖方向。记录每个非标准符号的含义、作用域、首次定义及后续使用次数；分类为 `core`、`keep`、`localize`、`inline`、`rename`、`delete`。排除约束变量、求和下标及标准算子。

在返回的 Markdown 中按下列标签和顺序填入七行；需要 `audit.md` 时由调用者在写入授权内保存。不要用“重载符号”“无关链”或文字摘要替换。分母为零时写 `0/0 (N/A)` 并说明无适用对象，不编造百分比。

```text
Core semantic objects retained: <retained>/<declared> (<percent>)
Undefined symbols: <count>
Symbol collisions: <count>
One-use definitions: <count>/<all new symbols> (<percent>)
Maximum parallel representations of one object: <count>
Maximum alias-chain depth: <count>
Maximum active nonstandard symbols in one proof step: <count>
```

## 阻断规则

把证明作为可用结果呈现前，核心对象保留率须为 100%，未定义符号和冲突均为零；没有适用核心对象时明确解释 N/A。

- **核心对象丢失**：改写删除、隐藏或替换定理的核心状态、策略或分布、算子、目标或依赖方向。坐标图不是其所参数化对象的替代品。
- **未定义符号**：含义及作用域尚不明确便出现。
- **冲突**：同一字形在整个材料中表示不同对象；不同下标不能修复基础含义变化。

核查是否优先保留既有或标准含义，对另一处提出重命名或删除建议，由获授权执行者改写。不能依赖遥远的章节边界消解冲突。

只有降低计算复杂度时才保留局部坐标；首次使用说明到核心对象的映射，并用核心对象重新表达每个主要定理、流或最终界。字形更少不能补偿数学接口的改变。

不能靠补入貌似合理的数学降低阻断计数。修复建议可重命名或内联有依据的表达式，但不可发明定义域、假设、导数恒等式、符号关系、定理前提或定义。权威材料未能解决时，保留计数，在报告中说明证明尚不可用。

## 警告阈值

### 定义收益

新符号至少满足一项才保留：

- 在后续至少三个公式中出现；
- 同时出现在定理陈述和证明中；
- 命名了后文会比较、变化或引用的对象。

约 12 字符或更短且最多出现两次的表达式宜内联。若展开会遮蔽长推导，可保留局部缩写，但作用域随该推导结束。

### 一次性定义

- 良好：不超过新符号的 10%。
- 警告：超过 10% 且不超过 20%。
- 较差：超过 20%。

一次性定义仅在紧接着的一句或一个公式中使用。不计约束变量和标准局部占位符。

### 并行表示

- 良好：同一对象至多两个持久表示，例如概率及其 logit。
- 较差：三个或更多持久表示。

第三种表示仅可留在一个局部推导内，小节结束即移除。

### 别名链深度

- 良好：一层，符号直接引用原始量。
- 警告：两层。
- 较差：三层或更多。

例如 `K := M+2`、`lambda := a/K`、`S := lambda x+b`，若末级仅服务一个不等式，应展平链条。

### 活跃符号负载

统计读者跨一个定理陈述、证明段落或连续公式链必须记住的非标准符号。

- 良好：至多 8。
- 警告：9–12。
- 较差：超过 12。

超过 8 时建议拆分论证、局部化定义或内联临时别名；不能为降低计数删除证明步骤。

### 定义距离

在首次使用前的段落内定义符号。局部作用域止于小节边界。除定理声明的全局记号外，读者不应跨章节寻找定义。

## 九步核查与改写顺序

reviewer 按以下顺序核查并返回修改建议，不直接改写；实际修复由获授权执行者使用同一方法完成。

1. 识别语义中心和依赖方向；完成条件：核心对象清单与原命题核对一致。
2. 查未定义符号与冲突，提出有来源的修复；完成条件：未解决者明确保留为阻断。
3. 列出可删除的未使用非核心符号；完成条件：每项建议均核对不影响核心对象。
4. 检查一次性定义能否内联、别名链能否展平；完成条件：建议与剩余超阈值项的理由明确。
5. 检查各对象的持久表示数量；完成条件：第三表示是否局部化或有理由已记录。
6. 对活跃符号仍超过 8 的步骤给出拆分建议；完成条件：推理依赖保留，剩余负载警告有解释。
7. 核对坐标结论到核心对象的映射；完成条件：每个主要结论是否保留原定理接口有据可查。
8. 复查全部代换和定理依赖；完成条件：等价性、定义域和引用前提均核对。
9. 给出删除冗余文字或显然代数的建议；完成条件：每个非显然转换仍可验证，返回报告中的七行计分表与实际受审正文一致，不用建议改写后的假想结果清零。

若更短的改写需要新增数学关系，输出诊断而不是伪装修好的证明。新名称确有数学含义时可保留较长表达。正确性及可验证的非显然步骤优先于低符号计数。
