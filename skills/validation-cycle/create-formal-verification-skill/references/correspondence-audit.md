# 对应审计：原问题、编码定义与定理声明

形式化检查能通过而仍然答错问题，最常见的路径是编码时换了题：定义被重写、量词被替换、边界被挪动、假设被悄悄加强。本审计逐项核对三者是否说同一件事，结论必须可追溯到原文与代码位置。

## 审计链

1. **原问题**：用户材料里的原始表述，包括它问的对象、量词、范围与期望结论。记录来源位置与原文，不用摘要代替。
2. **编码定义**：形式化中使用的类型、定义、前置条件与操作语义。逐条指出它对应原文的哪一句。
3. **定理／检查声明**：被证明或被检查的命题本身。写出完整陈述，含量词、假设与结论。

## 逐项核对

| 核对项 | 要回答的问题 | 不一致时的处理 |
|---|---|---|
| 对象 | 编码的对象是否就是原问题的对象，还是它的近似、特例或替换 | 记为换题；不得声称原命题成立 |
| 量词 | 「对每个」与「存在」是否保持，界内结果是否被写成全称 | 缩小声明范围或补足证明；不得默认提升 |
| 假设 | 编码新增的前置条件是否在原问题中成立，是否有证据 | 未证明的加强假设记为缺口 |
| 定义域与边界 | 空集、零、负值、下标、开闭区间、极限顺序是否一致 | 逐项列出差异与影响 |
| 结论强度 | 是否悄悄削弱（只证特例）或加强（多要求条件） | 削弱记为未完成，加强记为额外义务 |
| 外部依赖 | 引用的外部定理、公理、规范是否版本明确、条件满足 | 版本不明或条件未核者标未核实 |

## 不得冒充原定理成立

以下情况只允许作为候选、草稿或部分结果报告，并写出差距：

- 存在占位符、`sorry`/`admit` 一类未完成标记、未定义的假设或待办注释；
- 只有编译成功、构建成功或语法通过；
- 只有有限数值结果、抽样、界内模型检查或有限反例搜索；
- 编码声明与原问题在对象、量词、假设或结论强度上不一致；
- 外部依赖的版本或适用条件未核实。

「无占位符」与「编译成功」是必要条件，不是充分条件；有限数值结果可以提出候选、指出反例线索，但不能替代一般性证明。

## 输出

审计结果写入检查记录：每个核对项给结论（对应、有缺口、不成立、未核实）、证据位置与影响。被判定为换题或缺口未解决时，在交接中明说该检查回答的是什么、没有回答原问题的哪一部分。
