# Statistical Checks

[Analyze Results](../SKILL.md) Phase 2–3 的具体判断问题。每项结论必须给出实际文件与定位；不能定位即保持 `unknown`。

## 描述统计

1. 每个 reported 数字在哪个原始文件、哪个 key、什么值？metric 实现与配置文件是否一致？
2. 均值与 spread 的输入是哪些 attempts？它们的配置、数据划分、metric 实现是否真正可比？不可比的是否并列而非合并？
3. 相对提升的分母与分子分别是什么？算术是否正确（(new − base) / base）？
4. 趋势陈述的样本量是多少？单调、U 形、平台期的判断基于几个点？
5. outlier 如何处理？标记保留，还是删除／平滑？删除依据的规则是否事前声明？

## 重复与不确定性

1. 实际跑了多少 seeds/runs？报告了其中几个？spread 多大？
2. 结论对哪个子集敏感——去掉最佳或最差一次后结论是否变化？
3. 小样本（1–2 seeds）下的“稳定”“复现”措辞是否已降级为单点观察？

## 选择偏差

1. 是否只报告最佳 seed、最佳 checkpoint、最佳数据子集？选择规则是否事前声明？
2. 失败、超时、崩溃、被排除的 runs 是否保留原始记录？排除理由是否一致？
3. 是否存在 winner-only 汇总、被覆盖的旧结果、重用的 attempt 名称、静默排除？
4. 试过多少 metrics、配置、数据子集，报告了其中几个？分母是否写出？

## 失败与无效记录

1. 崩溃、超时、无效输出的原始记录在哪里？时间范围与输出位置是否完整？
2. “无效”是谁判定的、依据什么规则？事后排除是否明确标出，而非静默丢弃？
3. 负结果是否保留？它们对 Claim 范围施加了什么限制？

## 数字对应

1. 报告数字与原始文件的 key、值、聚合口径（mean/best/last）是否一致？
2. 比较双方的配置、数据划分、seed、metric 实现是否对齐？引用型 baseline 是否标注 `reported`？
3. 图表标题、表格内容与正文陈述是否一致？标题描述的是否是图实际显示的内容？

## 范围诚实

1. 实际测试了多少 scene/dataset/configuration，每个配置多少 seed/run？
2. 报告是否使用 "consistently"、"robust"、"extensive"、"comprehensive" 一类词？实际范围是否支撑这些措辞？
3. 每个 Claim 的 population、setting、metric、时间范围是什么？超出部分是否已降级？

## 事实分级

- `observed`：原始材料直接显示；
- `derived`：由已读材料经透明步骤推得（公式与输入必须写出）；
- `reported`：只在摘要或报告中出现，必须回溯到原始输出；
- `unsupported`：现有材料不能支持，不得升级为依据。
