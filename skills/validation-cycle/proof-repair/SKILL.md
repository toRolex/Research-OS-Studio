# 证明修复

用户主动启动的有限修复流程。输入是完整证明与待修问题；输出是获准范围内的证明修订、完整数学论证和自然 Markdown 修复记录。正文保持原生格式（Markdown 或 LaTeX）；下文 LaTeX 编辑/编译步骤仅适用于对应输入，普通证明不要求 LaTeX 或 Lean 环境。记录与正文分别授权。内部数学检视自行完成；所有承担审查结论的 review 只调用 按路径级联读取的 `proof-review`。本技能不启动其它顶层 Workflow，也不接入定时循环。

## 委托继承
Gates: none

本能力继承当前 `research-os` 委托的原目标、可读材料、写入范围、额度与停止条件。新文件可在已授权写域内创建；本次修复、完整复审、委托允许的下一阶段及其有限重试继续沿用同一授权，不为阶段切换或已覆盖的重试再次索权。修复始终以 reviewer 的单条 finding 和原命题为边界；新 finding 可记录，不能因此扩大写域。覆盖既有成果、扩大 finding 范围、改变目标或执行不在授权内的副作用，先停在相应动作并取得决定。

用户可独立点名本 Skill。独立调用时，以本次请求作为这一项工作的委托；若原命题/假设、待修 finding、可读依赖、精确写入位置、有限轮数或所需副作用范围缺失，只提出一组简短、有界的问题补齐缺口。未授权的部分保持只读或不执行，不要求先运行 `/research-os` 或 setup。编译只有在当前委托明确覆盖命令、运行范围与输出/副产物写域时才执行；否则保持未编译，并仅就用户要求的编译补充所缺授权。

## 1. 确认修复契约

从当前委托提取契约；只读取其覆盖的材料。发现新增依赖时，先核对它是否仍在授权读取范围内；超出时只请求该项读取许可。材料不全时列出缺项；既有批评是待核实输入，不能代替原文。按 [授权与记录模板](templates/repair-record.md) 记录本次有效契约：

- **Scope**：主目标及涉及的定理、引理、推论、定义和依赖边界；哪些问题不在本次范围。
- **完整目标**：逐字保留原命题，另列显式量词、定义域、参数区间、极限顺序、常数依赖、一致性范围；不清楚处由用户澄清。
- **不变量**：保持的命题、假设、结论强度、适用范围、符号/归一化约定和标签。新增假设或减弱结论必须再次由用户决定；reviewer 和任何下游 agent 均不能代替用户批准。
- **精确写入边界**：每个绝对文件路径、允许修改的段落/环境/唯一锚点、能否创建文件。证明正文、记录、附加引理、参考文献、可选审计报告分别列明；目录级笼统许可不能推导出任意文件写权限。
- **轮数**：使用委托中的最大修复轮数与总额度；每轮为一批数学修复、获准写入、完整 fresh 复审及该批必要盲审，失败或未完成也计数。补救与盲审发现的新修改在额度内进入下一轮，不因换阶段、线程或重试重置或重复确认。独立调用未给轮数时，在有界请求中补齐；授权没有覆盖下一轮时停止并报告。
- **工具与资源**：继承委托明确允许的本地来源、工具与资源预算。联网查询、数值/符号执行和外发按委托边界处理；每次对外发送仍须满足委托保留的具体决定门。既有工具可用不等于超出委托范围获准使用。
- **编译副作用**：LaTeX 写入本身不扩大编译范围。编译授权须覆盖现有编译器、入口、工作目录、实际命令、运行次数/时间及精确输出文件或限定构建目录/副产物；已在本委托覆盖时直接执行，不重复索权，未覆盖时不编译。不得安装环境或扩大副产物范围。
- **停止**：用户停止、轮数用尽、命题/假设需决策、写入/读取/外发范围不足、来源不可读、review 不可用、编译越权、上下文不能承载全文、出现冲突修改均暂停，说明保留了什么、阻塞在哪里、下一步需用户决定什么。

完成条件：目标、finding、写域、轮数及所需工具/副作用均可追溯到委托；未覆盖字段明确为“不执行”，而不是默认同意。无法同步获准命题变更的全部下游时，先停止，保留提案，不留下局部偷换后的正文。

## 2. 建立修复基线

读取 [数学义务账本](references/mathematical-method.md)，建立六份账本：依赖 DAG、假设账本、类型符号表、显式量化命题、微命题、极限顺序。账本中的“原文声称解除位置”与“审查确认解除”分开。分类、严重度、侧条件与闭合以 proof-review 为准，见该文件的指针。

读取 [复审契约](references/review-contract.md)。review 是裁决权威。已有审查须与本次完整原文逐项核对；缺少有效基线审查时，只经 `proof-review` 获取。按 review 的双轴记录状态、严重度、影响链、反例与最小修复方向。无数学命题则报告不适用并停止，不制造修复。

完成条件：每个问题可定位到完整原文，每个待修结果的上下游、假设和未解除义务可追踪；审查失败不视为没有问题。

## 3. 在委托轮数内修复

按 FATAL → CRITICAL → MAJOR → MINOR 处理，先尝试反例，再明确四选一：

1. **ADD_DERIVATION**：补足推导；新引理写出全部假设、命题与证明。
2. **STRENGTHEN_ASSUMPTION**：提出最小新增条件、其必要性与下游影响，用户决定后执行。
3. **WEAKEN_CLAIM**：提出准确的弱化结论、丢失的保证与可保留内容，用户决定后执行。
4. **ADD_REFERENCE**：完整阅读可用引用的相关定理、定义、假设和证明条件，在每个应用点逐条解除；题名、摘要、搜索片段或“标准结论”不足以替代。

先独立写完数学修复提案：原文 → 错误原因 → 反例/候选 → 完整推导 → 新义务 → 下游传播 → 验证方法。随后才在获准路径及段落写 LaTeX；可行时保留 `\label`，逐项更新获准的依赖应用点。数学正确性检查与 LaTeX 编辑是两步，不以语法补丁冒充证明。

每次写入前重新核对目标原文和唯一锚点；冲突即停。每轮累计保留原始批评、失败方案、撤回原因、实际改动与尚未完成的义务，不覆盖失败历史。

用户明确选择 `--deep-fix` 才读取并启用 [深修复模板](templates/deep-fix.md)。深修复提供可粘贴方案，不替代数学核查或授权；默认不生成其专有字段。

完成条件：每项改动有完整推导、明确策略、新增义务和获准下游同步；未获批方案只作为提案保留。

## 4. 编译及副作用边界

只有当前委托明确覆盖本次命令、已存在的环境、运行上限与产物/副产物位置时才运行编译；写入授权本身不自动扩展到未列明的编译副作用。对已覆盖的编译范围直接执行，不在各修复轮重复索权；范围缺失或越界时保持未运行，说明缺口并只请求补足必要范围。保留实际退出码、日志与实际产物位置。检查语法错误、未定义引用、缺失文献、标签冲突及警告；不能只凭过滤日志无输出宣布成功，不能把旧 PDF 当成新结果。编译成功不代表证明成立。

缺少工具、不获授权、超时或失败时分别写“未执行/不可用/失败”和原因；不安装依赖、不伪造通过、不自动扩大写入副产物范围。失败后只在现有授权与轮数内修补，否则停止。数学复审可对当前源码进行，但报告必须保留“编译未验证/失败”，不称完整交付已通过。

完成条件：实际检查证据已记录，或未执行/失败已如实呈现。

## 5. 全文复审与全局闭合

每轮按 [复审契约](references/review-contract.md) 调用 `proof-review`，发送当前完整原文及必要上下游原文，旧审查问题仅用来追踪，不用修复者摘要引导裁定。重大修复另做不接触旧批评的 fresh 盲审；任何新问题回到下一轮，受原上限约束。

随后按 proof-review 主文件的整体闭合核对当前原文。本侧只补 assumption delta：已经用户决定，并同步到获准下游。

用户选择 `--restatement-check` 才读取 [重述回归](references/restatement-check.md)。它是可选全篇检视，不把发现变成自动写授权；但已知受本轮改动影响的正文下游同步始终必做。

模型复审只是有边界的独立第二意见，不是形式化验证或数学真值保证，避免把“本次审查未发现阻断问题”写成无条件正确性认证。

完成条件：没有未解决 FATAL/CRITICAL；全部证明义务已证明或明确列为经用户批准的假设，所有量词、渐近常数与一致性范围明确，所有关键引理和修改下游做过反例尝试，必要复审/盲审完成。仍有 MAJOR 或 MINOR 时逐项列出并说明影响：任何开放数学义务都阻止“所有义务闭合”；纯表述问题可保留，但须解释为何不影响数学义务。依赖未验证导入时只能声称“以该导入为前提”。工具失败、计划写完、编译成功或轮数耗尽都不是证明通过。

## 6. 交付或停止

按 [授权与记录模板](templates/repair-record.md) 交付自然 Markdown：精确改动位置、每轮问题与完整修复、复审原文反馈、闭合与 assumption delta、编译实况、失败路线、已证明/仍假设/未解决的分界。不默认新增文件；未授权记录落盘时直接回复。

完成条件：记录含契约各项、每轮 BEFORE/AFTER、复审全文；未落盘则写明未落盘。深修复与重述回归只在对应 flag 已选时披露。

轮数耗尽仍未通过时，给出最小阻塞问题集；依次列出弱化结论、加强假设、补引理、重构论证的可挽救方案、可复用片段与作者下一步。方案均等用户决定，不静默切换目标。

用户可另行授权 LaTeX 审计报告，内容包括问题双轴总表、前后逻辑链、逐项反例与完整推导、义务差异、已证/假设/开放问题；可用 BEFORE 红、AFTER 绿、WHY WRONG 橙、KEY INSIGHT 蓝、WARNING 黄区分。报告输出须在当前写域内；编译与副产物仍按第 4 节单独核对，不默认生成 PDF、HTML 或启动渲染技能。
