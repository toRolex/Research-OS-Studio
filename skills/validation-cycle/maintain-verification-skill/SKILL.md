# Maintain Verification Skill：维护行为验证 Skill

特征映射在应用变化的瞬间开始腐烂。本 Skill 是 `create-verification-skill` 生成的项目本地 verify skill（或任何带特征映射的项目本地验证 skill）的维护闭环。严谨的单位是特征，不是每句话：每个特征文件都要有源覆盖，每个特征都要被真实驱动一次，不必对每个条目穷尽到底。

本 Skill 处理软件行为验证的维护；形式化检查（模型、性质、定理编码）的重新对齐由 `maintain-formal-verification-skill` 负责，两者不互替。

Gates: none

## 委托继承

一次调用继承本次研究委托的目标、权限与额度：启动应用、驱动特征、写验证资产与项目内依赖准备在授权内进行；越权、超额、未授权的全局安装或外部上传仍需用户决定。用户只要索引体检或只读源读时，保持该范围，不启动应用。需要按特征并行源读与独立复核时以当前会话确实可调用的子代理工具为前提；没有时该步标 blocked 并写明缺口，不由编排者串行代跑冒充独立复核。

## 结果分类

每一轮先选定并说明是哪一个结果：

- **clean**：每个特征都有源覆盖与真实驱动覆盖；无可交付修正。无分支、无 PR。
- **changed**：一轮已证明的文档、harness 或映射修正随分支交付。
- **blocked**：覆盖没有完成，或已证明的修正无法安全交付。写明具体被什么阻塞。

## 编辑范围

只改验证：只编辑验证 skill 自己的目录（SKILL.md、features/、它拥有的 harness 脚本）。运行期间不改产品代码：映射描述而应用不再做出的行为，要么是文档漂移（修映射），要么是产品回归（如实报告，不用文档遮盖）。

## 轮次

0. **定位目标。** 找到要维护的项目本地验证 skill：正文含启动/驱动小节与特征映射。多个候选时问用户是哪一个；没有时停止并指向 `create-verification-skill`，不凭空发明目标。

1. **索引体检。** 读特征映射索引，glob 同级文件，修复缺失、多余、重复或死链条目。不生成重型清单；本维护 Skill 独立安装时不依赖创建 Skill 的文件。

2. **源读波。** 每个特征文件一个只读子代理，并发启动。每个子代理回答「这个用户可见特征在源里怎么工作？」，带引证标出疑似文档漂移，并返回一个简洁的现场验证配方。子代理不驱动应用、不改文件。返回形状：特征摘要／源入口／疑似漂移或无／一条配方。没有子代理能力时整波标 blocked，主会话不串行冒充。

3. **对账。** 每个特征文件都有返回的摘要。把重叠的配方合并成尽量少的应用状态；抽查有引证的漂移，不为干净的结论重新证明。扫一遍近期变更，找映射缺失的用户可见表面——没有具体源路径不算「缺失」。

4. **现场驱动。** 源看起来干净也要做。协调者拥有全部驱动；遵循验证 skill 自己的启动模型——服务器和 UI 用一个长驻实例串行驱动，短命 CLI 每次驱动一个全新隔离会话（以 skill 的启动小节为准，不是本 Skill 说了算）。每个特征至少被驱动一次，并在整个轮次中守住三条不变量，无论失败与否：

   **证据归属与失效。** 本轮运行记录及交付的验证资产必须绑定实际对象：记录代码 revision、工作区脏改动差异（或明确无改动）、关键输入/数据与依赖和工具链版本、验证资产版本，以及适用范围与假设。相关代码、输入、依赖、工具链或验证资产变化时，立即将受影响结果标为 `stale`/待验证；保留旧证据作历史，但不得为新对象背书。重跑受影响覆盖并记录新对象绑定后才恢复为已验证；无关结果可保留原状态。

   - **先 doctor 再驱动**：第一次驱动前、会话制的每个新会话、任何一次驱动失败之后都跑 doctor；doctor 看不到的失败（进程健康但 UI 卡死）重置到已知状态或重启实例，不侥幸续用。
   - **证据在每次清理后存活**：在命名位置核对，不假设。
   - **驱动启动的东西不比驱动更有用**：失败迭代的残留一律清理，无论会话卡住、退出还是共享（共享实例清残留，不杀实例）。

   doctor 失败由 skill 漂移引起时按漂移处理：在编辑范围内修复，重试一次（重启被该修复作废的东西，不多不少），仍失败才叫 blocked。到不了某特征时，只有给出具体前置条件（认证、权限、操作系统、外部状态）和已尝试路径，才能记 `verified-unreachable`；映射漏写该前置条件本身就是漂移。triage 得到的 harness 修复在被驱动过一次真实验证后才可交付。最终拆卸在整轮最后一次驱动之后——包括那些复证——所以没有任何东西活得比这轮久（证据按 skill 约定保留）。

5. **Triage。** 错误或缺失的用户视角描述 → 文档漂移，修映射。行为存在但 harness 驱动不了 → harness 缺口，修它；harness 修复遵循与生成时相同的 helper 规则（脚本可执行、调用写在正文里）。应用行为确实坏了 → 产品缺口；记录给用户，不进本轮修正，也不削弱旅程制造通过。

6. **交付或停止。** changed：一轮已证明的修正交付，交付前重读每个改动文件。clean 或 blocked：不交付修正，如实报告结果与覆盖情况——包括仍未执行的覆盖，如实标为待执行，不冒称已验证。

执行失败、项目不可达或某轮未能完成时如实说明结果；清理后保留已采证据。把简短运行记录（覆盖了哪些特征、不可达前置、确认的漂移、结果）放在 scratch 位置，不提交，并遵守「证据归属与失效」合同。宿主中立：不写死宿主品牌、个人目录、固定模型或厂商专属命令。
