# Remote Execution Position

远程只是执行位置。Research OS 不提供 daemon、中央调度器、云供应商适配层或执行引擎；复用用户已授权的 SSH 和已有调度方式（例如现成 Slurm、PBS、队列 CLI 或云作业命令）。不锁定供应商；换位置只改变执行面，不改变授权、额度和科学判断。

不新造执行引擎：新的远程需求先映射到 SSH 或已有调度器的现有能力；无法映射时报告 blocked，不引入隐藏运行时。

## 授权与边界

- 使用已登记的远程范围、账号或队列、可写目录、并发、时间和费用上限；不申请新凭据、不扩大配额、不登录生产服务器做验收。
- 凭据只通过宿主或用户已有机制解析；Skill 不收集、打印或存储 secret 值。
- 上传代码/数据、下载结果、写入远程目录和清理实例都分别受授权约束；不把“能 SSH”当作全盘授权。

## 执行与恢复

- 在远程为主机建立独立目录，避免覆盖他人或旧作业；记录主机、用户（或别名）、工作目录、输入版本、工具链、命令和作业身份。
- 优先通过已有调度器查询作业；直接 SSH 时用目标主机的进程、日志或作业记录核实，不凭本地连接是否断开判断作业。
- 断线先查原作业：读取同一作业身份的调度器状态、远端日志和退出码；不盲重跑。作业退出、产物有效、科学结论分别判定；无法关联旧文件时按 `stale`/`unknown` 处理。
- 下载只授权的产物，保留远端原始路径和身份；清理付费资源按授权执行，不能清理时如实报告。
