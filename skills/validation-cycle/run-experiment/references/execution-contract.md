# Execution Contract

每次真实执行的最低合同是自然格式记录；不要为它新增 runtime 或统一 JSON 数据库。字段可分布在 run note、tracker、原始日志和产物旁边，但必须能互相回溯。

| 字段 | 记录要求 |
| --- | --- |
| 输入版本 | 代码 commit 或可核对快照、计划版本、数据版本、配置文件与 prompt/template 版本；不可变来源记录 revision，运行中生成物不冒充输入版本。 |
| 工具链 | 解释器、包管理、关键库和版本、硬件/驱动、容器或环境标识；项目内复现环境优先，不改全局配置。 |
| 独立目录 | 每个 job 使用计划授权内相互隔离的工作、日志和输出目录；共享只读输入可以复用，可写状态不重叠。 |
| 作业身份 | 本地进程、远程主机、SSH 会话或调度器给出的稳定 run/job id；没有 id 时记录启动时间、主机、目录和命令并说明限制。 |
| 命令 | 原样记录启动命令、参数、环境变量名（不记录 secret 值）、工作目录和启动者。 |
| 退出码 | 记录作业自身或调度器的退出/终止码、信号和终态时间；没有终态证据就保持 `unknown`。 |
| 原始日志 | stdout/stderr、调度器日志、指标流或 crash 报告的路径和读取范围；保留失败与被取代的日志。 |
| 产物 | 结果文件、checkpoint、图、表和指标的位置、大小、修改时间、内容摘要或校验方式；记录生成它们的作业身份。 |

## 判定分离

- **作业退出**：由退出码、信号、完成 marker 或调度器终态判定。
- **产物有效**：检查产物与作业身份关联、可读、未被截断或覆盖，关键 schema/完整性检查通过。
- **科学结论**：由计划成功标准、统计和独立审计判断；产物有效不等于结论成立。

旧文件只有在能证明来自本次作业身份且未被取代时才能用；否则标 `stale` 或 `unknown`，不接受为本次结果。
