# Claim 判定细则

[Result to Claim](../SKILL.md) Phase 1–3 的具体判断问题。每个结论必须给出实际文件与定位；不能定位即保持 `unknown`，不得因“没有反证”升级为支持。

## 一、Evidence 存在性（机械核对，无需审查者）

对每个引用了具体数值与来源的 Claim 逐项核对：

1. 来源文件是否存在？引用的是哪个文件、哪一段读取范围？
2. 该文件中是否存在声称的 metric key 或字段？
3. 文件中的值与引用值是否一致？口径（mean/best/last）、单位、有效数字、聚合范围是否对齐？
4. 引用是否写清“值 + 来源”？只写“实验表明”“显著提升”而不给数值或来源的，属于无法定位。

结论只允许：

- `verified`：文件存在且值确实在其中。这只证明证据**存在**；是否**支持** Claim 由第三节判定。
- `path_missing`：引用的文件不存在。
- `value_not_found`：文件存在但值或 key 不在其中。
- `unparseable`：引用没有可解析的值或来源。

`path_missing` 与 `value_not_found` 是**无证据引用**：对应 Claim 直接记 `unsupported（evidence-not-found）`，不再为它消耗审查调用。`unparseable` 正常进入第三节，但必须在报告中记录该引用缺口，不得当作 `verified`。缺席的 attempt 与来源保持 `unknown`，既不按通过计，也不按失败计。

## 二、统计可信度

判断支撑每个 Claim 的数字在统计上能走多远。已有 `analyze-results` 报告时采用其结论；否则逐项核对：

1. **重复与不确定性**：实际跑了多少 seeds/runs，报告了其中几个？spread 多大？去掉最佳或最差一次后结论是否改变？1–2 个 seed 下的“稳定”“复现”是否已降级为单点观察？
2. **选择偏差与分母**：是否只报最佳 seed／checkpoint／数据子集？选择规则是否事前声明？失败、超时、崩溃、被排除的 runs 是否保留原始记录、理由一致？“最好”“提升”陈述是否写出分母（试过多少、报了多少）？
3. **多重比较**：试过多少 metrics／配置／数据子集，报告了其中几个？只报最优的必须写明分母；未声明的探索性比较不得当作验证性结论。
4. **失败与无效记录**：崩溃、超时、无效输出的原始位置与判定规则是什么？事后排除是否明确标出而非静默丢弃？负结果对 Claim 范围施加了什么限制？
5. **数字对应**：报告数字与原始 key／值／聚合口径是否一致？相对提升的算术是否正确（(new − base) / base）？比较双方的配置、数据划分、seed、metric 实现是否对齐？引用型 baseline 是否标注 `reported`？

**一条线通过不替另一条通过**：数字对应无误不能证明没有选择偏差；重复稳定不能证明范围措辞诚实。不可重算项保持 `unknown`。

## 三、逐 Claim 范围与支持判定

先把 Claim 分解成可核对的范围要素，再判定：

- **population**：对谁／什么对象成立；
- **setting**：在什么任务、数据、配置、环境下；
- **metric**：用什么指标衡量、聚合口径是什么；
- **time**：时间范围或版本边界；
- **comparison**：与谁比较、基线是否公平；
- **intervention**：观察性关联还是受控因果。

把“在该固定设置观察到”与“普遍有效、因果有效、优于所有方法、已复现或已证明”分开。每个 Claim 只取一个结论：

| 结论 | 成立条件 |
|---|---|
| `supported` | 证据存在（`verified`）、统计可信、声明范围不超出实际测试范围 |
| `needs-narrowing` | 部分支持：证据只支撑更窄的范围，必须给出缩窄后的候选表述 |
| `unsupported` | 证据缺失（`path_missing`／`value_not_found`）、统计不可信，或反证成立；写明是哪一条断裂 |
| `unknown` | 关键材料缺失导致无法判定；没有反证不等于支持 |

完整存在的证据链也可能因统计或范围问题降级：`verified` 只解决第一节，不替第二、三节。

## 四、缩窄规则

`needs-narrowing` 必须产出可直接替换原 Claim 的**更窄表述**，禁止停留在“基本成立”“大致支持”“部分正确”。按断裂处选择具体缩窄方式：

- 一般概括 → 点名实际测试的 population／dataset／scene 子集；
- 因果措辞 → 降为关联陈述（除非设计支持因果）；
- “优于所有方法” → 收为“在配置 X 下优于所列基线”；
- “consistently／robust／extensive／comprehensive” → 删除，或补上实际分母与覆盖范围；
- 点估计 → 加不确定性限定（区间、种子数、敏感子集）；
- 代理指标结论 → 收为“在该代理指标上”，不表述为真实任务性能；
- 已复现／已证明 → 需要独立复现或证明链，否则降为单次观察。

缩窄后的表述必须仍是可检验的陈述，并保留其不确定性来源。

## 五、评价类型上限

按 `experiment-audit` 的评价类型给出支持天花板；类型判断缺失时记 `unknown` 并压低上限：

| 评价类型 | 可支持的 Claim 上限 |
|---|---|
| `real_gt`（数据集真值） | 在实测 population／setting／metric 范围内，统计成立时可支持 |
| `synthetic_proxy`（模型生成参考） | 只能支持“与代理参考一致”类陈述；不得支持真实任务性能或泛化结论 |
| `self_supervised_proxy`（设计上无 GT） | 只能支持代理目标上的相对改进类陈述；不得表述为任务正确性 |
| `simulation_only`（模拟环境） | 只能支持模拟设置内的陈述；不得外推真实世界迁移 |
| `human_eval`（人工评判） | 只能支持该评分协议下的质量陈述；须说明评分者选择、盲法与一致性 |
| `unknown` | 上限 `unknown`，不得写 `supported` |

评价类型上限低于 Claim 声明范围时，按第四节缩窄或改判，不能因数字漂亮而越级。

## 六、反证与缺口

每条判定都要附反证／缺口，逐项写定位：

- 不支持或限制该 Claim 的失败记录、负结果、异常运行；
- 未被测试的 population／setting／metric／时间范围；
- 使结论不成立的已知混淆因素或设计缺陷；
- 最小补证动作（补哪个 seed／baseline／子集／评价类型即可判定）。

补实验、补分析或修复材料本身不在本 Skill 内，只是提议；需要时由用户另行授权。

## 事实分级

- `observed`：原始材料直接显示；
- `derived`：由已读材料经透明步骤推得（公式与输入必须写出）；
- `reported`：只在摘要或报告中出现，必须回溯到原始输出；
- `unsupported`：现有材料不能支持，不得升级为依据。

只有前两类可作为判定依据。
