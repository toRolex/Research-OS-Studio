# 基础文档种子

在 Draft 时读取。以下为可裁剪种子，不是一次性复制的文件树。按实际文件角色复用已有文档；仅缺失项进入草稿。尖括号内容须依据已有材料或用户回答替换，不知道的项目事实先问或跳过。链接相对于承载它的文档计算，路径含空格时用 Markdown 尖括号目标。

## 工作区导航（缺失时建议 `<workspace>/README.md`）

```markdown
# <项目名称> · 研究导航

本项目的研究工作区位于 `<项目内实际工作区路径>`；已有材料原位保留。

- [项目说明](<项目说明的实际相对路径>)
- [Findings](<findings 的实际相对路径>)
- [研究日志](<日志的实际相对路径>)

## 已有材料

<仅列真实存在且与研究相关的材料位置；没有时省略本节。>
```

不另建空的 Idea、实验、证明、论文目录；导航中也不放这些尚不存在的占位链接。

## 项目说明（缺失时建议 `<workspace>/project.md`）

```markdown
# 项目说明

<从现有项目说明确认的范围，或用户提供的简短描述。只说明项目，不生成 hypothesis、Claim 或研究结论。>

研究材料沿用项目原有格式和位置；本导航不改变环境配置。
```

## Findings（缺失时建议 `<workspace>/findings.md`）

```markdown
# Findings

用于记录后续研究发现、来源位置、适用范围与不确定性。初始化未生成研究发现。
```

## 研究日志（缺失时建议 `<workspace>/research-log.md`）

```markdown
# 研究日志

后续按日期记录研究决策、尝试及原始材料位置。初始化未执行研究。
```

已有 findings 或日志时直接链接，不插入这段模板、不追加虚构日期或“实验完成”记录。

## Agent 指令文件中的区块

展示将被编辑的真实文件名和以下完整草稿；按 SKILL.md 的文件优先级选择目标。

```markdown
## Research OS

研究工作区位于 `<项目内实际工作区路径>`。处理本项目的研究任务前，先读 [研究导航](<相对指令文件的导航路径>)，再读取其中与当前任务相关的原始材料。材料保持原有自然格式和位置。

Idea Discovery、Validation、Paper Writing and Improvement 均由用户显式发起，互不自动启动。内部能力仅在当前授权职责、写入范围与资源内执行；缺少材料、工具或授权时说明缺口。

初始化仅补齐基础导航与说明；各 Workflow 的具体产物在用户首次授权使用时创建。环境、付费资源和远程副作用由项目用户决定。
```

三条流程是能力分类，不是对已安装入口的保证，也不要求用户按此顺序工作。
