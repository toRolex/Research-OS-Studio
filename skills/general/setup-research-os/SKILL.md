# Setup Research OS

这是 prompt-driven、user-invoked Workflow，不是安装脚本。用户显式要求初始化或补齐科研工作区时运行；安装 Skills 本身不构成写入项目的授权。模型负责探索、推荐、起草和验证，用户决定路径、内容冲突与最终写入。其他 Workflow 不自动调用本 Skill；本 Skill 不调用任何研究 Workflow 或内部 Skill。

输入是当前科研项目位置、已有材料及用户在对话中的选择；位置不明时先问清楚。输出是经确认的基础导航、项目说明、findings、研究日志及一个 Agent 指令文件中的 Research OS 区块。复用已有等价文件；文件名不是强制 schema。

写入范围仅限最后获批草稿列出的项目内文件和必要父目录。使用宿主现有读取、提问、精确编辑能力；能力或授权不足时报告缺口并停止，不安装补救工具。资源仅为本地探索及获批文件编辑；不读取凭据或无关私密材料，不配置 Python、Lean、LaTeX、GPU、SSH 等环境，不安装 Skills，不运行实验、联网检索、发布或 Git 操作。

## 1. Explore

只读检查当前项目，不假设是空目录或 Git 仓库：

- 确认项目根目录，读取适用的项目指令和 README 等入口。
- 检查根目录 `CLAUDE.md`、`AGENTS.md`，已有 `## Research OS` 区块和其中的导航位置。
- 查看可见目录、已有研究说明、findings、日志及材料索引；先读导航，再按需读相关材料。数据、代码、CSV、图片、LaTeX、Lean 保持自然格式。
- 查找已有工作区，例如 `research/`、`notes/`、`docs/research/`；仅检查真实存在的路径，不要求创建这些候选目录。
- 区分文件、目录、符号链接与不可读对象。指令文件是链接时，确认真实目标和是否同一文件；目标在项目外、链接失效或访问被拒时停止该写入，向用户说明，不能沿链接越界。

完成条件：能够列出项目根目录、现有导航和材料位置、基础文件缺口、指令文件候选及所有路径冲突；不可读取部分明确标为未知。

## 2. Present

简述发现：哪些文件将复用、哪些基础项缺失、哪些路径或内容需要决定。推荐公开可见的 `research/`（不是发布到互联网），但已有非空工作区优先沿用。材料原位保留，导航使用实际路径；不为统一外观搬迁、复制或重命名研究材料。

完成条件：用户已看到事实与建议的区别，以及预计写入范围；此时没有任何写入。

## 3. Ask

一次只问一个必要决定，推荐答案放在前面；已由材料或用户明确决定的事项直接沿用，不重复盘问。

1. 工作区有歧义时，询问沿用哪个现有目录；没有工作区时，询问是否采用 `research/`。已有同名非空目录可直接复用，但不能把同名文件当目录。
2. 项目名称、说明或基础文件角色无法从现有材料确定时，仅问缺失信息；也可由用户选择暂不补该项，不能代写科研判断。
3. 指令文件优先选已有 `CLAUDE.md`，否则已有 `AGENTS.md`；两者都有时只改前者。都没有时问用户创建哪一个，也允许暂不创建并如实报告未完成项。
4. 有内容冲突时读取 [冲突与重复执行规则](references/conflicts.md)，展示具体差异，再逐项询问保留现状、采用修订或暂不处理。不能把第一次安装授权当成覆盖许可。

完成条件：每个拟写入项的路径、用途和冲突处理都已确定；用户拒绝初始化时直接 Stop，零写入。

## 4. Draft

读取 [基础文档种子](templates/workspace.md)，只用所需部分起草；模板在本 Skill 内，不从中央目录取资源。用实际相对路径替换占位符。复用现有 README、项目说明、findings 和日志，不创建功能重复的副本。

向用户展示完整写入清单和草稿：新文件全文；已有文件的完整拟替换区块及带上下文的差异。每项注明创建、补齐或原位更新，以及保留不动的内容。导航只链接已存在或本批拟创建文件。通常最多补导航、项目说明、findings、日志四类基础文档及一个指令区块；只创建这些文件必要的父目录，具体 Idea、Claim、Evidence、实验、证明和论文产物留给用户以后显式调用相应 Workflow 时创建。

完成条件：每一处拟写入内容均已展示，无隐藏的后续文件或环境变更。

## 5. Confirm

询问是否按这份完整草稿写入，等待明确同意。沉默、推荐答案、单个路径选择和“已安装”均不算同意。用户修改草稿后重新展示受影响内容及最终清单，再确认；用户拒绝则零写入并停止。

若所有基础项均已存在且无需改动，报告“无需写入”并 Stop，不制造初始化日志或重复区块。

完成条件：当前版本的完整草稿获得明确写入授权，或已停止。

## 6. Write

写入前重新读取全部目的文件，核对其仍与 Draft 所见内容一致、新建路径仍未出现、真实目标仍在项目内。同时复查根目录 `CLAUDE.md`、`AGENTS.md` 两个候选的存在性、对象类型与真实目标，包括未列入写入清单的候选；核对指令文件优先级与选址前提仍成立。目的文件或候选状态变化时停止整批写入，展示新差异，回到 Ask / Draft / Confirm；例如原先只有 `AGENTS.md`，确认后出现 `CLAUDE.md`，应按新候选重新起草和确认，不能沿用旧授权修改任一文件。不能覆盖其他会话的新材料。

只创建缺失项；已有内容仅按批准的精确差异编辑。指令文件中的 `## Research OS` 区块原位更新，其他区块逐字保留；不存在时追加一次。区块边界或重复标题不明确时按冲突处理，不猜测删除范围。其他基础文件中的用户文字、日期、记录顺序和研究结论保持不动。

遇到写入错误立即停止，报告已成功和未完成的文件；不自行扩大权限、不做破坏性回滚，不把部分成功宣称为完成。恢复前重新探索并确认剩余草稿。

完成条件：本批获批内容已写入且无额外文件；或失败已明确报告并停止。

## 7. Verify

重新读取每个获批文件，逐项对照草稿：路径与正文匹配、链接目标存在、Research OS 区块仅一份、原有周边内容和材料保留、没有多余空目录或研究产物。不能只凭编辑工具返回成功就宣布验证通过。

报告创建、更新、复用、跳过的实际路径及未解决项；若有差异，展示事实，修复需要新草稿和确认。验证的是初始化文件，不是科研正确性、环境可用性或用户端到端体验。

完成条件：全部获批变更逐项核对，结果和局限已告知用户。

## 8. Stop

告知工作区导航位置，说明用户以后可以直接编辑这些 Markdown 文档；重复运行只补缺，不要求重置项目。到此停止。用户自行决定是否以及何时开始 Idea Discovery、Validation 或 Paper Writing and Improvement；不安装、执行或自动启动它们。
