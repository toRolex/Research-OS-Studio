# 冲突与重复执行

在 Explore 发现已有内容、路径冲突或指令区块不明确时读取本规则。默认复用和保留；用户未明确同意的差异不写入。

| 情况 | 处理 |
|---|---|
| 所需用途已有等价文档，名称不同 | 沿用真实位置，导航链接它，不再创建默认同名文件。 |
| 目标与草稿相同 | 不写入、不更新时间、不追加重复“setup 完成”日志。 |
| 原文件有用户内容 | 保留全文；只展示确实缺失的导航或区块的拟增补差异。用户改过的项目说明不是待覆盖的模板。 |
| `## Research OS` 已存在 | 精确定位此标题到下一个同级或更高层级标题之前，保留其他内容。检查代码围栏，围栏内标题不是区块边界。 |
| 同时有多个 Research OS 区块、类似标题或边界不明 | 展示所有候选和周边，询问保留哪个或如何整合；未确认不删除、不再追加。 |
| 两个指令名指向同一项目内文件 | 只按优先选中的入口更新真实文件一次，保留链接本身；记录真实写入目标。 |
| 目标是目录、路径父级是文件、链接越界或不可读 | 报告具体冲突并询问另选项目内位置或跳过；不删对象、不改权限、不覆盖链接。 |
| 确认后文件被修改或新文件出现 | 停止本批；重新展示与当前内容的差异，取得新确认。 |
| 用户选择保留现状或拒绝写入 | 保持该项原样；若造成导航指向不存在文件，从草稿去掉该链接并重新确认。 |

差异展示至少包含实际文件路径、原有内容、拟保留内容和拟新增/替换内容。可以展示 unified diff，但不能只说“会更新配置”。基础文件冲突同样遵守这套流程，不仅指令文件如此。

重复执行的完成标准是缺失项得到补齐或明确跳过；不是每次都生成新文件。发现用户自己的研究记录时，保留其内容与日期，不用种子模板重新初始化。
