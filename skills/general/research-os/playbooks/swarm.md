# swarm

用户要在有界额度内对一个问题做并行覆盖：多个执行者分片、竞赛或混合探索，得到一份带证据、缺口与退出情况的汇总。本路线是编排链路：入口 → swarm 能力 → 汇总验收。

## 适用

已有明确问题或任务，覆盖面比单次执行大，需要并行子代理分片排查、多方案竞赛或分片内竞赛。只要推荐入口走 route-only；单一路线的常规执行走对应叶能力，不必包一层 swarm。

## 阶段角色

Role: orchestrator

Frame、Aggregate 与 Report 由编排者执行；Fan out 派发子代理。

Role: implementer

worker 按项目角色表 `implementer` 行解析模型。

## 步骤

1. 读[研究委托合同](../references/mandate.md)，确认目标、写入边界与额度。缺项按有界首轮处理，不因缺 setup 停下；只有目标替换才确认。
2. 读 `skills/general/swarm/SKILL.md` 全文，按 Frame 要求写明完成条件、组织形态（分片、竞赛或混合）与选择规则（`first pass` / `rank all` / `best-of`），并为四个阶段各开一条 todolist。读过本 playbook 不等于读过正文。
3. 按正文 Fan out：宿主当前会话确有子代理工具时才并行派发，brief 逐份独立、输出隔离；没有子代理工具时本步骤标 blocked，写明缺的是宿主子代理能力，不用编排者串行代跑冒充 swarm 已执行。受阻时仍可给只读建议，但不得记成本委托已完成。
4. Aggregate（必做）：逐份核对结果与 brief 点名的证据；缺证据的有界重派一次，二次缺失记缺口；缺口不算通过，也不算覆盖。
5. Report 并收束：交回合并报告（对照表、问题摘要、缺口与掉线、竞赛规则），记录已消耗额度与未覆盖范围，供 pickup 恢复。

## 完成条件

swarm 要的汇总已交付，且第 4 步的核对项各有「已验证」或「缺口」的明确标注。并行覆盖不是正确性证明：报告不得把竞赛胜出或分片齐备说成原命题成立。

## 停止

委托目标达成、用户叫停、额度用尽或第 3 步 blocked 即交付并停止。全部 worker 掉线或证据二次缺失占多数时如实报告缺口收束，不自动加赛或重开整轮。
