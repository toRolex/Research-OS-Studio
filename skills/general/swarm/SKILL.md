# Swarm

## 委托继承

Gates: none

由 `/research-os` 的 `swarm` 路线级联进入时，本调用继承调用者的研究委托：目标、权限、研究额度与完成条件沿用，读这份正文不再重复请求批准；只有目标替换才停下确认。独立调用时，用户点名本能力时给出的目标、写入边界与额度就是本次授权范围，不需要先 setup。

本能力按委托合同迁移，条款与已迁移清单由调用者持有；本文件只声明 swarm 自己的执行规则。验收看实际产物，不看 worker 自述：每次派发都要在额度内，收束时保留成果与可续接状态，不把缺口说成完成。

## 来源与许可

本能力改编自 `cursor/plugins` 仓库 `pstack/` 插件的 `skills/swarm/SKILL.md`（固定 revision `88d47514b82e7c44f00f2b2a72ff6dd12158038c`，MIT 许可，作者 Lauren Tan；许可文本随本目录 LICENSE 共置）。改写范围：去掉 Cursor cloud、固定模型名与个人规则目录绑定，改为宿主真实子代理与项目角色表解析；补齐证据缺席的有界重派、缺口登记与委托合同衔接。机制骨架（Frame / Fan out / Aggregate / Report）与上游一致。

## Start

派发任何 worker 前，先在 todolist 里为四个阶段各开一条，逐步跟踪：

1. Frame
2. Fan out
3. Aggregate
4. Report

## Phase A: Frame

1. 写明完成条件（done predicate）与 swarm 必须交付的产物或报告。派发前这条要能被 worker 的结果逐条对照。
2. 选组织形态：把任务切成互不重叠的**分片**；或让 N 个 worker 拿同一份 brief 跑**竞赛**；或两者**混合**（分片内再竞赛）。竞赛或混合形态必须在 Fan out 之前声明选择规则：`first pass`、`rank all` 或 `best-of`，不得事后补。
3. worker 模型按项目角色表 `.agents/research-os-models.md` 的 `implementer` 行解析（`Role: implementer`）。角色表或该行缺失时，沿用调用当前会话的模型，并在报告里写明这一点。模型竞赛（不同模型跑同题）时，在 Frame 里点名每个 arm 的模型。
4. 每个写入结果的 worker 有自己的可写输出位置（输出隔离）：互不共用文件路径，brief 里写明各自写到哪里。worker 要核对或测量具体提交时，brief 写明确切的 SHA 与方法（样本量、单个样本是什么、顺序），worker 在结果里同时记录两者。

## Phase B: Fan out

用宿主当前会话确实可用的子代理能力，在一条消息里并行派发全部 N 个 worker。宿主没有可用的子代理工具时，本阶段标 blocked，写明缺的是宿主子代理能力，不用编排者自己串行代跑冒充 swarm 已执行；用户仍可直接点名底层能力单做其中一件事。

每份 brief 独立成立（独立 brief）：包含目标、范围、确切的分片或竞赛 arm、如何验证、要报告什么。读者不需要再看其他 brief 或编排者上下文就能开工。结果报告用 `PASS`、`ISSUES` 或 `BLOCKED` 加证据；能证明缺陷的 worker 报 `ISSUES` 并列出它能证明的每一个问题，不只报第一个。

某个 worker 掉线或失败时，用剩余 N-1 个继续，并在报告里记录掉线情况。

## Phase C: Aggregate

逐份读取终态结果，按 Frame 声明的标准核对：

- 结果没有记录其 brief 点名的证据（如 SHA、方法、输出位置）时，不算通过：剩余额度允许时最多重派一次，brief 里补写证据要求；否则直接记为缺口。第二次仍缺，记为缺口。
- 缺口不算通过，也不算分片覆盖；在报告里如实列出，不以推测或部分结果填补。
- 分片形态：每个必需分片都要有一份合格结果才算覆盖。
- 竞赛形态：按派发前声明的 `first pass`、`rank all` 或 `best-of` 规则选择。
- 汇总用编排者自己的话，不整段粘贴 worker 原始输出。

## Phase D: Report

交回一份合并报告：结果对照表、问题一句话摘要、缺口与掉线清单；用了竞赛时写明所用的选择规则。报告写明哪些结论已验证、哪些因缺口或掉线未验证，以及未覆盖的范围，供调用者或下一次会话续接。
