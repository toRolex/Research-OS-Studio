# 会话边界：仅在用户询问上下文延续时阅读

改编自 Matt Pocock `ask-matt/PHASE-BOUNDARIES.md`。这里的边界是一段咨询或研究工作结束、用户决定下一步的时刻，不是全局 phase，也不由 Router 维护。正在进行的推理优先保留原上下文；本页只帮助用户选择，不执行任何会话命令、写交接材料或派发任务。

以下决策只在工作结束边界使用；推理中途默认继续，或建议在后续授权内拆出独立任务，不主动压缩／清空。

## 按顺序判断，首个符合者优先

1. **Continue：能在当前会话继续吗？** 下一项仍依赖原始推理，或上下文余量足够，优先保留它。原始材料比摘要更能保留限定条件与失败路线。这里的“继续”仍需用户另行调用研究入口，不代表 Router 自动执行。
2. **Clear：旧上下文完全无关吗？** 只有它对后续确实可丢弃时，才建议用户使用宿主实际支持的清空方式。误删相关上下文会丢失决策理由，不能靠重读结果完全恢复。
3. **Handoff：真的需要可移植交接吗？** 换宿主、换目录／项目、交给同事或分出旁支任务时，才需要可携带的材料与范围说明。同宿主同目录并不自动需要交接。若需要新交接文件，由用户另行授权处理；Research OS 不假定存在名为 handoff 的已安装 Skill。
4. **Subagent：工作可独立且范围明确吗？** 后续任务不需要用户持续决策、且宿主有隔离能力时，可建议在该任务自己的授权内独立阅读原始材料并返回报告。Router 不在本次咨询中派发，也不把摘要评审当独立原件审查。
5. **Compact：其余情况再考虑压缩。** 仍在同宿主同目录、上下文相关且需要用户参与，但余量不足时，建议使用宿主实际支持的压缩方式，并保留目标、证据位置、未解决问题和授权范围。不假定固定 token 阈值或特定命令存在。

## 取舍与停止

Continue 保留一手上下文；压缩／交接通常用有损摘要换空间或可移植性，独立代理的返回报告也不是其所读原件。需要关键判断时仍应回到原始材料。这些是有顺序的判断问题，不是自动规则。建议说清理由与信息损失后停止，实际选择交给用户。
