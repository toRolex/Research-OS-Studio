# File and Tool Capability Audit

Purpose: keep the boundary visible between methods bundled in this Skill and file readers, OCR engines, connectors, renderers, or external services supplied by the host. This is a support-scope audit, not a promise that every format works everywhere.

| Need | Existing bundled coverage | Host prerequisite / limit | Decision |
|---|---|---|---|
| Search plain text / Markdown | Search strategy, source logging, and synthesis methods are bundled in `SKILL.md` and `source-methods.md`. | The host must expose readable files or an authorized search connector. This package does not provide a general file-indexing engine. | Reuse the existing host reader/search capability; do not add another search Skill. |
| Read and extract born-digital PDF text | The local-paper workflow specifies bounded screening and evidence capture. | A PDF reader or host extraction capability must be available and actually return text. No PDF parser is bundled. | Use an available authorized reader; unreadable files remain explicit gaps. |
| Read scanned PDFs / image-only documents | The method directs the user to an existing authorized reader/OCR capability. | OCR, layout/table extraction and image understanding are host/tool prerequisites; no OCR model or conversion executable is bundled. Accuracy must be checked against the page image for material claims. | Do not install or claim OCR coverage. Mark scanned/unreadable documents blocked when no existing tool can extract them. |
| Reference-manager and notes connectors | Retrieval steps cover accessible reference-manager libraries and research notes. | A real host connector with existing authorization must be discoverable; mentioning Zotero, Obsidian or another service does not install or authenticate an integration. | Reuse only available connectors; missing connectors reduce coverage and are reported, not added as package dependencies. |
| Plotting and diagram production | `academic-plotting` bundles methods, templates, references and license texts for chart/diagram work. | The user project must already have a suitable interpreter, libraries, fonts, diagram renderer, and image/PDF reader for the selected task. Environment probes are allowed by its contract; dependencies are not installed by this package. | Reuse academic-plotting; report actual missing runtime capability. |
| Figure export and visual inspection | Plotting references discuss PDF/SVG/PNG export and inspection. | Export requires the chosen renderer; visual review requires the host to open/read the actual exported file. A successful script or file extension alone is not an export/inspection guarantee. | Preserve editable source and report formats actually produced and inspected. |

## Audit conclusion

In the present bundle, research methods are supplied for source search, text/PDF triage, connector discovery, plotting, and figure export; general-purpose file conversion, PDF extraction/OCR, reference-manager connector implementations, chart libraries, fonts and renderers are not. These are explicit host prerequisites, not bundled capabilities. No additional external asset is selected in this ticket: the target host and a concrete required conversion/OCR workflow are unspecified, while adding a parser, OCR engine or connector implementation would introduce runtime/dependency and license obligations beyond the current text-method bundle. This is a scope decision, not a claim that no suitable licensed asset exists. Do not advertise host prerequisites as bundled features; revisit asset selection when a target host and concrete gap are identified, then verify the candidate's license, resource reachability and dependencies before adding it. No new Skill, package dependency, connector list, OCR promise or renderer is added merely to increase feature count.
