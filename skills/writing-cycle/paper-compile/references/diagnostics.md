# 异常诊断与源结构

## 八类诊断

对每条日志 error/warning 记录原文、源文件/行号、根因证据、影响及候选处理；先查首个根因再看级联错误。行号可能来自被 include 的文件，按日志上下文定位。check-only 只建议；修复模式仅应用当轮已获用户认可的具体 diff。下表八类全部保留；表外错误也记录为独立诊断，不强行套类。

| 类别与信号 | 核查方法 | 有证据的处理与停止边界 |
| --- | --- | --- |
| 缺包：`! LaTeX Error: File 'somepackage.sty' not found.` | 检查拼写、项目随附样式、可信本地 TeX 搜索结果，区分文件漏带与工具链缺失。 | 报告缺失组件由用户准备；只有证明包完全未用且不影响模板时才提删除 `\usepackage` 的 diff。不能自动 `tlmgr`/系统安装或下载。 |
| 未定义交叉引用：`LaTeX Warning: Reference 'fig:xyz' ... undefined` | 检查实际 `\label{fig:xyz}` 是否存在、拼写/重复、所在图环境及 label 与 caption 顺序；确认 include 可达和多遍是否完成。 | 将错误 ref key 对到真实 label，或为真实对象提 label 修正；不编造对象，不拿旧 aux 消除警告。 |
| 缺图：`File 'figures/fig1.pdf' not found.` | 检查路径大小写、工作目录、扩展名 `.png`/`.pdf`、`\graphicspath`，核对已有文件确实是该图。 | 仅对真实对应图提出 `\includegraphics` 路径/扩展名 diff；没有图则阻塞，不造图、不用占位图掩盖失败。 |
| 未定义引用：`LaTeX Warning: Citation 'smith2024' ... undefined` | 检查 cite key、实际 bib/bbl、后端选择和 `.blg`，先排除文献链未跑或语法错误。 | 可修正到已有真实条目；新增条目须有可核验元数据来源及用户授权。无法核验就标待确认，不编造作者、标题、DOI 或引用。 |
| `[VERIFY]` | 搜索所有范围内源稿与新 PDF 文本，含被宏/换行拆分的可疑变体；追到具体待核验事实或引用。 | 记录每个位置、所需证据及影响；可向用户索取真实资料。保留标记，不直接删掉，不把编译通过当事实核验。 |
| `Overfull \hbox (12.5pt too wide) ... lines 42--45` | 记录每项超宽值、行号并对照页面。上游 >20pt 是优先检查的严重提示，小值也可能越界或影响匿名稿排版。 | 建议缩合文字、合法断行、核对真实图宽；微小且视觉无影响可记低优先 warning。不能统一忽略、全局缩字号/页边距绕过模板。 |
| BibTeX 语法：`I was expecting a ',' or a '}'---line 15 ...` | 读取对应 `.bib` 与 `.blg`，检查缺逗号、括号不匹配、标题特殊字符、重复 key；Biber 的对应语法/数据错误亦保留。 | 对真实条目作最小语法 diff，保持文献语义和元数据；修复后完整重跑文献链。 |
| 自定义定理的 `\crefname` 未定义/名称缺失 | 核对 cleveref 已加载、`\newtheorem{assumption}` 定义及顺序，区分命令根本不存在与类型名称未注册。 | 适用时在对应 `\newtheorem{assumption}` 后的前导区补 `\crefname{assumption}{Assumption}{Assumptions}`，其他类型按实际定义处理；先解决包/模板冲突，不盲加宏。 |

编码、宏展开、包冲突、权限、后端不匹配等非表内问题：保留完整错误上下文，定位最小相关输入；不能为了“八类齐全”漏掉其他错误。成功构建仍保留 underfull/overfull、rerun、未定义引用及其他警告，区分本次中间遍已消除与最终遍残留，附对应日志。

**完成条件：** 全部观察到的错误和警告都有处置状态；没有把“没找到”当“零个”，没有把未执行的修复列为完成。

## 孤立 .tex 检测

从已确认入口建立依赖图，递归追踪 `\input`、`\include`，解析有无 `.tex` 扩展名、相对目录、嵌套路径与实际宏上下文；项目使用 import/subimport 等机制时一并纳入。枚举项目范围全部 `.tex`，而不只比对 `sections/*.tex` 与 main 的文本。

处理注释、`\includeonly`、条件宏、动态文件名和生成输入：静态不可判定时记“条件不明”，不要当不存在。辅助入口（supplement/回复信/模板示例）分别建立根节点。若构建产生 `.fls`，用本次实际读取路径补充证据；“本次没读到”只证明当前配置未激活，不能排除其他条件分支。

输出三类：可达（入口与链路）、候选孤立（在已分析根与配置下无链路）、条件不明（宏/条件/外部路径证据不足）。对旧结论章节之类残留建议用户核实归属，**不删除任何 .tex**。

**完成条件：** 范围内每个 .tex 已归类，递归链路或无法判定原因可查；没有以 basename grep 充当完整可达性分析。

## 有界修复的诊断顺序

仅 user-invoked 修复入口使用：原文 → 文件/行号 → 有证据的最小 diff → 用户认可 → 应用 → 新空目录重编译。首轮基于已有可信日志或经授权的基线构建；最多三轮“应用 diff + 构建”，文献内部多遍不是多轮。连续两轮无进展时，暂停重读全部日志，复查包冲突、编码与宏；向用户提出人工复核或基于现有能力的独立分析选项，不绑定或自动调用任何 provider/插件/agent。第三轮只有尚有预算且当轮 diff 已认可才执行。

**完成条件：** 每轮有对应证据、许可、精确 diff 和构建结果；达到预算、无进展、新风险或需扩权即停止，未授权部分保持原样。
