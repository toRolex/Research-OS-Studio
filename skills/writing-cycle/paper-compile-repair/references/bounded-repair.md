# 有界修复的诊断顺序

仅本修复入口使用：原文 → 文件/行号 → 有证据的最小完整 unified diff → 按授权来源核对并向调用者展示、记录 → 应用授权覆盖的 diff → 新空目录重编译。独立调用按文件、diff、工具/命令、构建目录、副产物、安全条件与预算取得明确许可；有效父委托已覆盖目标、写域、普通有限修复和执行条件时，记录覆盖依据后直接执行，不要求未来每个 diff 再获用户批准。尚未形成的 diff 仍须先完整展示；这项展示不等同于重新索权。目标/假设替换、新副作用或越出既有写域/资源预算时，只暂停受影响动作并取得新增授权；未授权的外发、收费或资源批次仍须停在动作前。诊断分类与孤立 `.tex` 检测见 [paper-compile diagnostics](../../paper-compile/references/diagnostics.md)。首轮基于已有可信日志或在授权内执行的基线构建；最多三轮“应用 diff + 构建”，文献内部多遍不是多轮，重试与恢复不重置实际额度。连续两轮无进展时，暂停重读全部日志，复查包冲突、编码与宏；向调用者提出人工复核或基于现有能力的独立分析选项，不绑定或自动调用任何 provider/插件/agent。第三轮只有尚有既定预算、授权覆盖且当轮 diff 已展示并记录才执行。

**完成条件：** 每轮有对应证据、授权来源/覆盖映射、完整 diff、基线/构建目录/副产物与真实预算记录；未覆盖的写入、目标替换、外发/收费/资源批次或新风险停在动作前，未授权部分保持原样。TeX 输入闭合性审阅、现有可验证 sandbox 与并发源复核仍遵循 [安全构建](build.md) 及其权威构建合同。
