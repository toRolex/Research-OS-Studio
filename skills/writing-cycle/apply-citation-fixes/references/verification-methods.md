# 来源核实方法

本方法由 ARIS 的 citation-audit、citation-discipline 与 reviewer-independence 改编，随本 Skill 的 MIT LICENSE 发行。detect 全程执行检索与核实；apply 在展示方案前及写后复验时执行。查到来源、字段正确、支持主张是三个独立结论。

## 1. SEARCH：具体查询与来源选择

记录输入条目的标题、完整作者顺序、年份、venue／journal、DOI、arXiv ID 与版本；保留原值，不先改成猜测的“正确”数据。优先具体查询：

- 标题 + 第一作者；
- 方法名 + 数据集 + 第一作者；
- claim 关键词 + 作者；
- 标题中特有短语的精确查询。

无结果时检查标题／作者拼写，添加年份和第一作者，缩为独特短语再查询；记录实际查询词、来源、读取结果及日期。相似标题不能直接视为同一篇。

| 来源 | 主要用途与限制 |
|---|---|
| DBLP | CS／ML 的作者、会议记录与直接 BibTeX；极新论文可能尚未收录，约两周内尤其注意，回退 arXiv／官方会议记录 |
| Crossref 与 DOI 登记／解析记录 | 已有 DOI 的登记元数据与出版入口；解析失败不证明不存在，登记质量与可访问性可能不同 |
| arXiv | 已有 ID 优先查对应论文和版本；保留 preprint 年份与版本，不能充当已发表 venue 的唯一证明 |
| Semantic Scholar | 发现、模糊标题搜索、摘要和交叉核对；注意限流，搜索摘要不是最终 claim 证据 |
| OpenAlex | 跨源身份／元数据核对；字段约定可能不同 |
| ACL Anthology、OpenReview、出版社／期刊和正式 proceedings | 原始发表记录、作者、正文、附录及版本状态；OpenReview 投稿存在不代表接受 |

ML 发现从 DBLP／Semantic Scholar 入手；已知 DOI 从登记与出版记录入手；只有 arXiv 线索先读 arXiv，再交叉核对 Crossref／Semantic Scholar。已有 arXiv ID → 对应记录；缺失或未确认 → DOI；仍不能确认 → 标题模糊查询。模糊匹配只是候选筛选，不是身份通过阈值。Google Scholar 可提供线索，不以人工搜到片段替代权威元数据及原文。

只用当前已有、允许使用的浏览／检索／读取能力；不要求固定工具、接口或安装脚本。受限时使用用户已提供的论文与出版记录，注明本地证据和在线未核实范围。无可读来源就逐项未核实，不凭记忆构造文献。

## 2. VERIFY：引用身份与版本

尽量以至少两个可信来源交叉核实同一篇论文，优先包含原始出版／预印本记录，例如 DBLP + DOI、arXiv + Semantic Scholar、DBLP + OpenAlex。不是把同一个摘要的镜像计成两份独立证据。仅单一来源时保留其能证明的事实，同时说明交叉核对缺口，不伪造第二来源或静默宣称完整核实。

同一身份最低比对：高度一致的标题、第一作者、完整作者顺序、相同或可解释的年份、匹配的 DOI／arXiv ID。多个相似候选逐一比较标题细节、年份、作者顺序、摘要主张，必要时读论文首页和正文。一个真实 DOI 指向另一篇论文是身份冲突，不是小拼写问题。

分别标出 preprint 和已发表版本，检查 v1／v3 改题、作者变更、不同年份、论文扩展版。正式版本通常优先，但引用特定定理／实验只存在于 preprint 时保留该明确版本；不能把旧版标题、会议年份与另一版内容悄悄合并。OpenReview 记录与最终 proceedings 均可能有效，按真实状态引用。

身份结论：已确认／身份冲突／未核实。来源未返回结果、网络错误、DOI 不解析、格式损坏分别记载，不能推导为“不存在”。只有可指出具体证据的错误记录才标确认错误或伪造；搜索耗尽本身仍是未核实。

## 3. RETRIEVE：逐字段元数据

优先来源顺序：已有项目条目先核实 → DBLP 直接 BibTeX → DOI 可用的 BibTeX 记录 → 其他官方记录。自动获取不是必需条件；只在权威元数据已充分时手工整理候选条目，并标出字段出处。所有获得的 BibTeX 都是待验证输入，不因机器提供就正确。

逐字段比较：标题（包括版本）、全部作者及顺序／变音符号、年份、venue／journal、entry type、DOI、arXiv ID／版本，以及原条目存在的卷、期、页码、URL、publisher 等。每项区分正确、拼写／格式瑕疵、错误、未核实。正确格式的作者名也可能幻觉；匿名占位先查发表状态或匿名约束；自己的旧论文也检查年份。

六人以上作者的 `and others` 常为合法缩略，不自动当作者幻觉；只有不符所用规则或隐去用户明确关注作者时标问题。样式允许的大小写、venue 缩写不要当实质错误。

元数据无法确认时在报告显示明确缺口，不向正文／bib 写假占位项。沿用项目引用 key 与引用系统，不为了整洁更换排版体系。候选新增／合并条目先检查条目类型、作者完整性、年份与 venue、key 冲突、是否已有同一论文。重复 key 不同身份须先解决范围歧义；同身份双 key 的合并须检查所有用法并单独授权。

## 4. VALIDATE：每一处 claim 语境

reviewer 必须自行读取被引论文的原始正文，对每个引用位置逐一比较：本文声称什么，原论文实际建立什么，范围／条件在哪里。记录原始 URL／文件、版本、章节／页／定理／表／图与具体证据。

- 对宽泛主题陈述，直接读取原始标题、摘要或引言可能足够，但要说明证据深度；主题相似不等于支持。
- 对“首次证明”“证明一般结果”“优于某基线”“发现因果关系”等负载主张，读相关定理和假设、方法、结果表与对照设置。证据无法充分读取时只能标 UNVERIFIED；只有实际读到充分原始证据、确认仅支持较窄范围时才标 WEAK。摘要或搜索片段不足不能推出弱支持。
- 检查任务、数据集、实验条件、比较对象、指标、量词、时间范围、因果／相关、定理／猜想，以及负结果是否被说成正结果。优先权“首次”还需相应历史证据，不能从某篇论文存在推出。
- 不能从另一篇 related work 转述继承结论；回到被引原始论文。多个 key 共同引用时分别说明各自支持的部分，以及是否仍有无人支持的子主张。

每处结论：SUPPORTS（支持所写的精确范围）、WEAK（仅部分／有限条件支持，需收窄）、WRONG（与主张不符或相反）、UNVERIFIED（所需原文未能读取）。同一 key 在引言错误、related work 正确时保留两行。元数据正确绝不冲掉语境错误。

例：论文讨论迭代改进，不等于证明“自反馈必然造成相关错误”；论文仅猜想某结果，不等于已证明。应根据实际原文判断，不把例子中的结论当当前来源事实。

## 5. PROPOSE：核实后才建议加入或替换

只有身份、必要元数据和目标 claim 支持充分核实的来源才进入可应用方案。已有本地条目可以复用但仍要核实；查不到就给补证动作，不创建似真的新文献。每个 replacement 写出目标位置、旧引用、新来源、支持证据与替换后句子；不能找到更好来源时提出受证据约束的收窄或撤回，而非保留无支撑断言。

对写入候选检查 BibTeX 逗号与大括号、特殊字符／标题保护、变音符号和项目已有编码规则。精确 diff 与用户授权属于 apply 的独立步骤；本方法的检索／建议不授权任何研究材料修改。

完成核对：身份与版本、所有现有字段、每处语境、替代来源、来源可读性及独立 reviewer 状态各有结论。没有全文、第二来源或独立 reviewer 的缺口分别披露，不用“已核实”一词笼统覆盖。
