# 轮次方法

[research-improvement](../SKILL.md) 的披露参考：审查、修复、验证与停止的可复用规则。它不是自动调用链，也不授予任何写入或运行权限；具体 scope、写入范围、轮数、预算与副作用仍以第 1 节授权门为准。

## 1. 审查者输入与裁决结构

审查者是独立的高级审稿人，从当前 artifacts 出发，**假定工作某处仍有问题并去找出来**。给它的输入只包含：当前 Claims/正文、方法或代码、原始结果（逐字文件，不是执行者整理过的表）、本轮前的 diff 与历史 findings。

每次审查要求给出：

1. 分数（1–10，标准由本次问题约定）；
2. verdict（如 ready / almost / not ready，词表本次固定，不在轮次间漂移）；
3. 按严重度排序的 weaknesses；
4. 每条 weakness 的最小修复（实验、分析或重新框定）；
5. 对关键数字与声明的独立核对（数字是否与结果文件一致、比较是否公平、配置是否混用、caption 是否与图一致）。

审查者未被要求制造发现：确实正确时直接说正确；核不动的项标 `unverified`，不补造结论。分数与 verdict 必须同时达标才算正面结论——高分但「not ready」不停止循环。

## 2. 独立性

- 每轮全新审查上下文；不复用上一轮的私有线程记忆或「作者已修好 X」的叙述。
- 只把当前 artifacts 与历史 findings 原文交给审查者；修复摘要、承诺与执行者解释都不作为评审证据。
- 完整原始回应逐字进入轮次日志；不摘要、不改写、不据其润色。
- 审查者不可用或独立性无法建立时，标 `independent review not performed` 并降级为单执行者评估；模型审查只是有边界的第二意见，不等于科研真值或用户接受。

## 3. Claim 校准（双向）

校准的目标是让声明**恰好等于证据支持的范围**，而不是一律加对冲。修复时同时检查两个方向：

- **真正超出证据**（scope、modality、比较方向或聚合方式超出支持范围）：收窄声明本身，而不是换一个更软的同义说法掩盖范围问题。
- **已被证据支持却裹着过度谨慎**：去掉多余对冲，保留使声明成立的范围限定词。
- **分散的通用 caveat**：集中到 Limitations，删除正文中的重复。
- **自辩与「我们不声称」、指令式坦白（「本文不处理 X」）**：作为写作缺陷删除，不留在正文。
- **叙事缺陷**：进度报告式结构（「先试了 A，再试 B」）、围绕方法落败指标组织的故事、把结果写成失败、没有论证任务的实验、以背景或实现开场而缺少 problem → gap → idea → strongest result、结论以新的自我否定收尾：在证据允许时重新框定与删减，证据不允许时中性陈述并把真实弱点留在 Limitations。
- **语气编辑不得改变事实、negation、modality、scope、比较方向或数字**；不得为「讲故事」删除表格中的不利数字，也不得把弱点包装成 tradeoff。

## 4. 有界修复模式

| 问题 | 修复模式 |
|---|---|
| 数字/配置/聚合与原始结果不符 | 修正为可定位的原始值；重跑对应的 result→正文核对 |
| 真正 overclaim | 收窄到支持的 scope/modality，而非换软同义词 |
| 支持结论被过度对冲 | 删除冗余对冲，保留必要的范围限定 |
| 通用 caveat 分散 | 合并进 Limitations，删除重复 |
| 叙事建立在落败指标上 | 围绕论文真正占优的对照重新组织；证据支持时把差距解释为目标差异或 tradeoff，否则中性陈述并收窄声明；表格数字全部保留 |
| 实验没有论证任务 | 删除、缩短、移入附录，或重新设计使其证明方法/机制/目标场景价值或排除替代解释 |
| 引用缺失或元数据错误 | 只增加可核实的来源；核不动的标记为未核实，不编造 BibTeX |
| 证明结构或记号变化 | 只改获批范围；做重述回归并保留未解除义务 |

每条修复先给出「原文 → 问题 → 最小改动 → 影响面」，再动文件。高严重度优先，先去重再执行；同一问题跨文件时同步所有 restatement（abstract、intro、method、experiments、theory、conclusion、表格、caption），一致性指 scope 一致，不是把 disclaimer 抄遍全文。

## 5. 写入边界与拒绝编辑日志

- 路径与操作都受第 1 节写入范围约束；冻结语义时拒绝新增引用、`\bibitem`、定理环境或新数值等操作。
- 每次修改前重新读取目标原文与唯一锚点；文件被外部改动或冲突时停止，请用户重新确认，不覆盖。
- 被拒绝的编辑（越出写入范围的具体编辑动作）与未解决项（对应 finding 仍未解决：含越界无法修、scope 内受冻结语义／外部依赖阻塞、需新证据或需用户决定）分开记录：rejected 入「被拒绝的编辑」，unresolved/blocked 入「未解决 Findings」，不把二者当成已修或静默丢弃。
- 被拒绝的编辑记入轮次日志：目标文件、原因（路径越界 / 操作越界）、命中的限制、对应的 reviewer finding。日志是审计轨迹；拒绝不中断本轮其余修复。
- 可在授权门中约定每轮最大编辑数；达到上限时把剩余修复顺延到下一轮并说明，而不是悄悄超量；若已无下一轮（轮数用尽），剩余修复按未解决项记录。

## 6. 验证与回归

- **构建验证**：正文类修改后跑真实构建（如 [paper-compile](../../paper-compile/SKILL.md) 的 check-only，或项目已有命令）；代码类修改跑项目已有测试或最小可复现检查；分析类修改重新对账数值与原始结果。保留实际命令、退出码、日志与产物路径；无可运行构建时如实记 `build not applicable` 并说明所用的对账替代路径。编译成功只说明文档能构建，不代表证明或科研结论成立。
- **重述回归**：定理/引理/命题/推论的**陈述**（不含证明正文）在正文与附录等位置间必须保持一致。做法：去注释与 `\label`/`\ref`/`\cite`，折叠纯格式宏，保留量词、情形划分、假设与对象名，按 label 优先、否则按类型与顺序比较；假设、情形划分、量词顺序或术语（如 stationary 与 terminal）变化都算回归漂移。漂移即回到修复步，不把回归留到交付。
- **结果回归**：正文数字与原始结果、表格、caption 在每轮后重新对账；发现漂移按 finding 处理。

## 7. 停止门与回退调试

- 正面停止需分数与 verdict **同时**达标；否则继续到轮数上限。
- 分数回退或停滞时，先比较相邻两轮的原始审查回应，找出翻转的具体判据，再决定修复；轮次日志是摘要，原始回应才是证据。
- 不自动续轮、不自证 acquittal（不拿自己产出的结论当停止依据）、不因重试或换框架重置预算。

## 8. 过程状态

循环的持久化就是本轮次日志与基线快照：读取日志可恢复每轮分数、findings、修复位置与未解决项；未授权落盘位置时，轮次日志即 [research-improvement](../SKILL.md) 第 8 节交付的报告正文，恢复依赖该报告。不建立 JSON 状态机、私有线程记忆、SHA/trace/receipt 或统一 schema；上下文受限时读日志与快照恢复，不凭记忆重建历史。
