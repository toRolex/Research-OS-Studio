# Academic Plotting

将 ARIS `paper-figure` 的图表交付方法与 Orchestra `academic-plotting` 的数据图、示意图方法组合。产物是用户项目中的自然格式图、源文件和可读说明。

## 授权边界

默认 **model-invoked**：只在当前已授权的图表职责内调用；用户也能点名 **standalone**。**composed** 接收父任务指定的图号、原始材料、写入范围、资源预算与主报告位置，只返回／贡献图表部分。父任务的消息不是额外用户授权。

- 输入：真实数据及其来源／单位／实验条件，或方法说明及组件关系；可选图表计划、现有图片、用户模板及目标尺寸。没有计划时，只探索用户指定材料位置，提出候选图表并确认选择。
- 写入：仅批准的图表目录（含源脚本、局部样式文件、可编辑图源、导出图、表格、caption、可选 LaTeX 引用片段）及指定报告区块。同名产物冲突先询问或使用已批准的新路径。
- 资源：默认本地、已有环境、一次生成及至多一次局部修正。先确定时间／图数上限；父授权更窄时从窄。外部数据读取须在授权来源内；远程上传、模型图像生成、付费及独立 reviewer 的外部调用须有明确内容／预算授权，否则停止对应分支。

## 1. 盘点并选图

读完整相关数据、方法上下文和已有图，不只读上游任务摘要。按 [figure-note.md](templates/figure-note.md) 的字段记录每个图号、目的、来源、类型、输出路径及授权范围；简单单图可直接用报告中的一个小节，无需制造空文件。

| 内容 | 本能力处理方式 |
|---|---|
| 数据图／比较表 | 每个数值可追溯到给定原始文件、字段／行与变换；不可由图像生成器绘制定量证据 |
| 架构／流程／概念示意图 | 从方法提取组件、边、方向和精确标签；标注“示意图／Schematic — not experimental evidence” |
| 真实照片、截图、模型生成样本网格 | 只使用已有且允许使用的素材，保留出处；没有素材时列为缺口，不补造 |
| 混合图 | 逐 panel 区分证据和示意；图注解释各自来源，不让示意部分承担结果证明 |

有数轴不一定是实测图：理论曲线须提供公式、参数、假设并标作理论／模拟；玩具数据只能在用户明确要求时作为标注的演示，不能填充缺失科研结果。

**完成条件**：每张图已分类，所需来源可读取，已有图保护范围、图数及写入位置明确；缺失或含混的来源／单位／关系列出具体问题，暂停该图。

## 2. 检查现有能力

先读项目环境约定，定位用户已有解释器／绘图工具并做最小导入或版本探测。只检查当前选定分支所需能力：Matplotlib 数据图不强制 Seaborn、SciPy、LaTeX 或远程模型；简单示意图可用 SVG 文本源或已有 DOT／TikZ／Mermaid 工具。

Python 操作使用已有 uv 和明确的现有解释器。例如替换为实际绝对路径后执行 `uv run --no-project --offline --no-python-downloads --python /existing/venv/bin/python -- python -c 'import matplotlib; print(matplotlib.__version__)'`。这是能力探测，不是安装命令；先确认路径存在。运行图脚本也用该环境，不加依赖声明、`--with` 或同步操作；选择不带安装副作用的项目已有运行方式也可。缓存／中间渲染文件安排在批准的临时或输出目录。

缺库、工具、字体或渲染读取能力：报告实际探测命令、错误及受影响产物，停止该分支。可提出使用现有替代工具或仅交付可编辑未渲染草稿，获准后执行；未运行、未渲染和未目检分别标明。远程生成可用也不等于已获上传权限。

**完成条件**：选定工具实际可用且副作用在授权内，或该图有明确阻塞说明；不以环境补装作为后续步骤。

## 3. 按类型制作

### 数据图／表：来源先于造型

读取 [data-visualization.md](references/data-visualization.md) 的选定模式、[style-guide.md](references/style-guide.md) 的最终尺寸／图注规则，以及 [table-and-review.md](references/table-and-review.md) 的表与符号规则。类型、映射、汇总与导出按这些文件执行。

**完成条件**：每张图／表的数据映射和变换可查，源文件可编辑且运行命令完整；无资料的单元格明确为空缺。

### 示意图：语义先于风格

读 [diagram-generation.md](references/diagram-generation.md) 的完整六段设计方法；选风格时再读 [diagram-styles.md](references/diagram-styles.md)。实体、边、设计说明、图源与示意标注按这些文件执行。

**完成条件**：每个实体／箭头能回指说明，示意身份可见，存在可编辑结构源，生成与未生成的部分明确区分。

## 4. 实际运行并复核

逐个审核后运行本次批准的脚本／导出命令，不对目录内所有脚本通配执行。记录工作目录、解释器与依赖版本、输入位置、命令、退出状态和输出。生成失败保留错误；不把旧图的存在当成本次成功。

然后读取**实际导出的图**，按最终打印尺寸检查轴／单位／图例、截断、重叠、字体、灰度可辨性、箭头方向和全部标签。SVG／PDF 包装不自动意味着内容矢量或文字可编辑。不能读图时只报告执行与静态结果，视觉检查待完成。

使用 [table-and-review.md](references/table-and-review.md) 的质量提示，逐项将 caption 与全部 plotted rows／方法说明核对。任何反例须收窄结论或改为描述；审查发现不能通过篡改数据修复。可在授权预算内做一次局部图形修正，重新导出并复核，仍失败则列明待解决项。独立 reviewer 可用且获授权时读取原始数据与渲染图，而非只收到 caption；否则明确“仅自查”，不伪称独立审查。

**完成条件**：每图都有“数据对应／运行／渲染目检／自查或独立意见”的实际状态及缺口；模型意见不等于科研真理或用户验收。

## 5. 交付并停止

standalone 在批准目录保存填写后的图表说明；composed 将相同信息贡献到授权主报告区块。交付必须写明：产物路径、复现命令、caption、未查项、已停止。引用片段仅是片段。

停在图表候选完成／部分完成／阻塞。许可证见随包 [ARIS MIT](LICENSE-ARIS.txt)、[Orchestra MIT](LICENSE-Orchestra.txt)。
