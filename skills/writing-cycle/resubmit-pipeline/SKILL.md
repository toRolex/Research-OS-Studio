# Resubmit Pipeline：保留旧稿的转投适配

用户显式调用的独立 Workflow：把已有的现成论文适配到另一个 venue，在新目录生成投稿材料，旧投稿保持原样。输入可以是任何现成稿件，不要求先运行本产品的写作流程、setup 或其他 Skill。

## 授权与边界

- 只有用户本次主动点名才进入；其他 Workflow、agent 消息、评审或日志中的建议不能启动它，也不构成任何写入或投稿授权。
- 旧投稿目录及其中一切文件始终只读；新材料只写用户本次明确批准的新目录与报告位置。目标目录已存在、非空或指向旧稿时停止，不覆盖、不合并、不清理。
- 用户决定 venue 选择、模板冲突取舍、是否继续适配、每处正文与引用改动、是否自行投稿。规则缺失或冲突未决时交付标注冲突的暂定方案，不代选、不称合规。
- 只交付候选材料与核验报告；不向任何外部投稿系统提交、上传或发布，不自动生成缺失的实验结果、定理证明、数据或引用。
- 默认只使用用户提供并允许读取的本地材料和已有宿主能力。额外检索、在线模板下载、付费资源或远程写入先确认数据范围和预算；无授权时保留缺口，不安装或配置环境。
- 无固定 provider、模型名、隐藏状态或结构化 sidecar 依赖。路径冲突、写入被拒或范围不明时停止并说明，不换工具绕过拒绝。
- 内部能力只在当前授权职责内使用：`paper-compile` 只读检查，`citation-audit` 只做检测；`paper-compile-repair` 与 `apply-citation-fixes` 各自仍需用户另行显式调用与逐项授权，本 Skill 的调用不代替它们的授权。不自动调用 `rebuttal`、`paper-talk` 或任何其他顶层 Workflow；需要时交用户另行点名。

## 输入与预算

收集旧投稿真实目录、目标 venue／年份／track／投稿阶段、官方 guidelines 与模板来源、输出目录、评审意见（如有）、已授权的读写范围与资源预算。默认在对话中展示计划，不先创建目录。

起草适配前确认官方指南的来源 URL、读取日期与适用范围；用户自带模板与官方规则冲突时展示差异，由用户决定。官方材料不可访问时保留未核实项，不用旧年份或第三方规则冒充最新要求。评审意见只是可选输入：有则按其逐条处理，无则只做 venue 适配，不编造评审 concern。

默认最多两轮“适配→检查→修订”。独立审查沿用各内部能力的自有预算；预算耗尽、达到上限或授权到期即停，交付未解决项，不追逐全绿。

**完成条件**：旧稿范围、新目录、venue 依据、输出授权、资源预算明确；缺失或冲突已向用户提出，未决时只返回阻塞项。

## 1. 锁定旧稿并建立新目录

先读现有新目录候选、旧稿目录内容及用户既有改动；恢复依据是实际文件与用户选择。展示拟新建目录与文件范围，取得写入许可；写前再次核对目标路径及其实际指向，防止链接或同名目录把写入带到旧稿或范围外。

按 [适配方法](references/adaptation-methods.md) 的“旧稿保留与新目录规则”执行：新目录与旧稿同级或位于用户批准的其他位置，不嵌套进旧稿；旧稿文件以普通文件复制进入新目录，保持相对结构，不使用符号链接、硬链接或跨目录 `\input` 指回旧稿；复制后逐文件比对内容一致。图、宏、样式、文献源随稿复制，不复用旧稿的构建产物（PDF／aux／bbl）充当新稿输入。旧稿的版本控制状态与内容基线在适配前后各核对一次，任何变化都是边界异常，停止并报告。

**完成条件**：新目录仅含本轮复制与新建文件、旧稿内容基线前后一致、复制清单可核验；任一条件不满足即停止。

## 2. 适配新 venue 模板

读取目标 venue 当前官方模板与指南，按 [适配方法](references/adaptation-methods.md) 的“模板适配”重建新目录的入口、导言区、文类命令与文献样式：新入口只引用新目录内的文件；文献样式按源稿实际链（BibTeX／Biber）匹配 venue 要求；页数、匿名、字体、附录边界按官方口径记录。用户模板与官方冲突处逐项列出，由用户决定采用哪一版；决定前不改相关文件。

适配中发现缺模板、缺宏包、缺图或缺文献源时记为缺口，不下载未授权资源，不删减正文凑页数，不改字体边距规避限制。页限溢出按方法中的收缩顺序逐项提建议，由用户逐项决定；每项落实仍受后续检查与授权约束。

**完成条件**：每处模板改动有官方依据或用户决定记录；缺口与冲突逐项可见，无未授权改写。

## 3. 只读检查与引用检测

在新目录上运行已实现的内部能力，均为只读，不改任何研究材料：

- 用 `paper-compile` 按其正文做一次 check-only 编译验收：真实构建（如获临时写域与预算批准）或静态诊断；报告构建状态、错误原文与位置、PDF 核验逐项结果。失败只报告，不在本 Skill 内修复；需修复时提示用户另行显式调用 `paper-compile-repair`。
- 用 `citation-audit` 做一次 detect-only 引用检测；soft-only（冻结 bib）默认开启：bib 不增删改，只给正文收窄或撤回主张的建议。需改 bib 或正文引用时提示用户另行显式调用 `apply-citation-fixes`，本 Skill 不展示其 diff 也不代替其授权。

两个结果都保留未核实项并说明检查覆盖缺口；旧稿 PDF 不能冒充新稿构建成功，无新 PDF 的检查单列未检查。

**完成条件**：编译与引用各有独立报告贡献或明确未运行原因；所有修改建议仍是建议，无一已应用。

## 4. 用户确认改动并转交授权修复

把第 2–3 步的全部候选改动（含模板适配 diff、编译错误拟议、引用收窄建议）逐项展示给用户：每个实际目标文件、当前位置与拟议内容、依据与影响范围、残余问题。用户逐项决定采用、拒绝或暂缓；全部拒绝或暂缓则零研究材料写入，返回保留问题后停止。

用户批准的正文改动由本 Skill 在授权范围内应用：写前重读目标文件核对无外部变化，应用后比对实际变更与批准内容一致。涉及 `paper-compile-repair` 或 `apply-citation-fixes` 职责的改动（源码编译修复、bib／引用标记改动）不在此应用，必须由用户另行点名那两个入口并走它们的精确 diff 授权；本 Skill 只记录待转交项，不代行。

**完成条件**：每项候选都有明确决定；已应用项与批准一致，无越界修改；转交项已列明入口与待授权范围。

## 5. 复验新稿并交付

对最终新目录重跑第 3 步的只读检查（编译验收与引用检测），核对本轮改动无新增错误、无引用断裂、无旧稿污染。仍失败或仍有 warning／未核实项时如实保留，不以旧 PDF 或上一轮结果冒充成功。

按 [适配报告模板](templates/adaptation-report.md) 以自然 Markdown 交付：旧稿基线与不变证据、新目录文件清单、venue 依据与冲突决定、检查与检测结果、已应用与拒绝／暂缓／转交项、未解决项与补证动作、实际报告路径。报告落盘仅在本次批准的具体路径；composed 不适用（本 Skill 不被其他 Workflow 自动调用）。交付后停止，不投稿、不发布、不启动 `rebuttal`、`paper-talk` 或其他 Workflow。

**完成条件**：报告与事实一致，未完成工作无虚假成功；旧稿只有零变更的核对记录，新稿候选材料与报告已返回或写入。
