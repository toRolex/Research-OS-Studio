AutoResearchClaw

aiming-lab/AutoResearchClaw · HEAD be4ba47
23 阶段状态机

定位：从主题、文献、假设、实验一路做到论文、质量门禁和引用验证的完整科研 pipeline。

实际目录骨架

researchclaw/
├─ pipeline/       # 阶段、合同、执行器、runner
├─ literature/     # OpenAlex/S2/arXiv、引用验证
├─ experiment/     # sandbox/Docker/SSH/Colab/Agent
├─ llm/ domains/ prompts/
├─ agents/ memory/ knowledge/
├─ hitl/ server/ web/ mcp/
├─ templates/ assessor/ evolution/
└─ cli.py + __main__.py
experiments/arc_bench/  tests/  docs/

主执行流

researchclaw run
→ config/preflight/run_dir
→ stage-01…stage-23
→ literature → synthesis → hypothesis
→ experiment design/code/run/refine
→ analysis → decision
  ├─ REFINE → stage 13
  └─ PIVOT  → stage 8
→ paper draft/review/revision
→ quality gate → export → citation verify
→ artifacts/.../deliverables/

阶段分层

  • 1–3：主题初始化、问题拆解、搜索计划
  • 4–8：收集/筛选文献、知识卡、综合、假设
  • 9–15：实验设计、代码、资源、运行、分析、决策
  • 16–23：论文、审稿、质量、归档、导出、引用验证

关键产物

  • stage-04/candidates.jsonl、references.bib
  • stage-12/runs/、results.json
  • stage-14/experiment_summary.json
  • deliverables/paper_final.md、paper.tex、verification_report.json
真实实现特征：每个 stage 有 input/output contract、Gate、健康检查；论文写作读取真实实验注册表和原始指标，避免无实验数字进入论文。
边界：外部 ColliderAgent 只有指针 README；部分 MCP handler 是 stub。本次只做代码核查，未执行真实 pipeline。
源码证据路径

Auto-claude-code-research-in-sleep（ARIS）

wanshuiyin/Auto-claude-code-research-in-sleep · HEAD 94d8093
Skill / helper 组合

定位：不是常驻应用，而是让 Claude Code/Codex/Gemini 等宿主 Agent 按 SKILL.md、helper、MCP 和文件协议执行科研。

实际目录骨架

├─ shared-references/   # 状态、审计、review 合约
├─ skills-codex/        # Codex 镜像
├─ skills-codex-claude-review/
└─ skills-codex-gemini-review/
tools/                  # 47 个 helper
mcp-servers/            # 7 个服务

aris-monitor/

默认 pipeline

安装 tools/install_aris.sh
→ Claude Code 读取 /research-pipeline
→ idea-discovery
  文献 → idea → 查新 → pilot → proposal
→ experiment-bridge
  写代码 → Codex review → sanity → GPU → results
→ auto-review-loop
  外部 review → 修复 → 重跑（最多 4 轮）
→ NARRATIVE_REPORT.md
→ AUTO_WRITE=true 才进入 paper-writing

文件化状态

  • .aris/runs/<run_id>.json：阶段状态与恢复
  • .aris/traces/：review 请求/响应取证
  • idea-stage/、refine-logs/、review-stage/
  • NARRATIVE_REPORT.md：默认研究终点

研究 Wiki / ARA

  • research-wiki/ 用 paper/idea/exp/claim 节点建图
  • ARA compiler：输入 → 知识提取 → coverage check → Seal Level 1
  • Rigor reviewer 只审 ARA，不执行代码、不抓 URL
真实实现特征：研究记录、review receipt、provenance、assurance 状态被当作一等产物；实验和论文之间通过结果/claim 文件连接。
边界：仓库本身没有完整研究工作区；模板定义了 research-state.yaml、findings.md 等，实际产物要在用户项目中生成。

THU-Team-Eureka/EurekAgent · HEAD fb96df8
LangGraph 实验搜索

定位：把 Claude Code 变成并行实验研究员；控制器负责多轮 propose/implement，隐藏 evaluator 独立评分。

实际目录骨架

├─ nodes/

├─ artifacts.py history.py ranking.py
├─ monitor/ tui/ prompts/
└─ time_budget.py resume_preflight.py
examples/ results/ .claude/skills/

LangGraph 拓扑

START
  ↓
prepare
  ↓
propose（生成 manifest + approach.md）
  ↓
implement（每个 approach 并行）
  ↓
propose ← 循环
  ↓
end

终止：max_loops / cost_limit /
无有效结果 / 合同不完整 / 连续 API 错误

单轮实现流

approach_details/<id>/code/
→ agent 实验与提交
→ eureka_submit.py POST /grade
→ grader Docker 读取 hidden_eval
→ score / valid / feedback
→ best_result.jsonl
→ history/ranking
→ 下一轮或结束

安全隔离

  • grader 与 agent 分离，agent 看不到 hidden_eval_dir
  • 实现 agent 只能写自己的 approach 目录
  • 提交通过 controller client，不能直接改 best/intermediate 结果
  • GPU 通过锁文件分配，不信任 agent 自传 GPU ID
真实实现特征：它更像“可验证的实验/优化搜索器”，不是从文献到论文的全链路；核心价值在并行方案、隐藏评分、结果排序、可恢复运行。

当前源码执行流

horizon init
→ config + .archon-horizon + Git ledger
→ 编译 skills/subagents

horizon run <target>
→ load workspace / inbox / MCP
→ build_orchestrator
→ scheduler 选 queued Task
→ HorizonAgent → Claude/Codex harness
→ transcript + report + checks
→ ledger integrate + events
→ 下一轮 / run.finished

任务调度与产物

  • scheduler 按 priority，跳过冻结任务和 write-set 冲突
  • 运行目录：.archon-horizon/runs/<id>/sessions/
  • 会话产物：transcript.jsonl、meta.json、report.md、usage.json
  • 证明结果：Lean、blueprint、hgraph、checks、Git provenance

图与 Dashboard

  • horizon graph sync：LaTeX label / Lean declaration → 节点与边
  • 离线搜索：BM25、声明名、signature pattern
  • Live server 默认 127.0.0.1:8765
  • dashboard --static 可导出 API 数据和静态页面
关键事实：当前 Python Orchestrator 是 Horizon-only；Ground 仍作为 native subagent 描述存在，但不是 Python 编排器自动交替执行。
仓库 docs 仍保留旧的 Ground 交替模型描述；当前源码和测试优先。这个项目的“研究输出”主要是形式化证明与其 provenance，不是论文 PDF。
